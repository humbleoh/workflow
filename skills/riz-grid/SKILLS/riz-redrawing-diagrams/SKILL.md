# 按图重绘架构图（redrawing-diagrams）

## 核心原则

Mermaid/PlantUML 默认自动布局，位置是「钉」出来的，不是「希望」出来的。**未渲染（或坐标审查）对比原图前，转换不算完成。**

## 工作流

1. **读图盘点**：组件清单（含分组嵌套层级）、每条连线（起点/终点/方向/标签/实虚线/颜色）、整体朝向（上→下分层 or 左→右流程）。
2. **按决策表选格式**；用户指定了格式则按指定格式做，但必须遵守该格式的能力边界（见下）。
3. **按对应格式的钉扎技术输出代码**。
4. **渲染验证（必做，不可跳过）**，逐项对比原图：
   - mermaid：`npx -y @mermaid-js/mermaid-cli -p pptr.json -i x.mmd -o x.png`，其中 `pptr.json` 内容为 `{"args":["--no-sandbox"]}`（无此配置 Chromium 沙箱报错）。
   - plantuml：`java -jar plantuml.jar -charset UTF-8 -tpng x.puml`。
   - draw.io：无轻量 CLI，验证方式 = 逐格审查坐标（同行 y 一致、同列 x 一致、无负值、无重叠、父子关系正确）。
   - 对比项：组件齐全？分组正确？**组内左右顺序**？箭头方向与标签？实/虚线区分？→ 不一致则改代码重渲染。
5. 无法精确还原时，明确告知用户哪里是近似，不要静默交付错位图。

## 格式决策表

| 原图特征 | 格式 | 原因 |
|---|---|---|
| 同层横向连线、跨层回边、自由/交错布局 | **draw.io** | 唯一支持绝对坐标，能精确还原 |
| 纯层间单向流的分层图 | mermaid `flowchart TB` + subgraph | 声明顺序即可钉位 |
| 左右流程/管道/workflow | mermaid `flowchart LR` | 声明顺序即从左到右 |
| 时序图 | mermaid `sequenceDiagram` | participant 声明顺序 = 列顺序，`box` 分组 |
| 类图 | mermaid `classDiagram` | 成员声明顺序即位置 |

## draw.io：位置精确还原

- 以原图左上角为原点，按比例估算每个组件的包围盒（画布尺寸取原图长宽比，如 0–1200 × 0–700）。**±10% 误差即可，不要像素级测绘原图**（收益极低）。
- 同一行组件 y 相同（±5），同一列 x 相同；行距/列距保持原图比例。
- 嵌套分组：容器 cell 用 `vertex="1"`、style 含 `container=1`，成员 `parent="容器id"`，成员 geometry 相对容器原点。
- 连线：`edge="1"` + `source`/`target`，用 `exitX/exitY/entryX/entryY`（0–1 比例）钉端点位置；虚线 `dashed=1`；颜色 `strokeColor`。
- 原图中悬空的元素（独立文字标注、单独的箭头符号、图例）：用独立 text/triangle vertex + 绝对坐标钉位，不要硬塞进边。

## mermaid flowchart：位置近似还原

- 整体朝向匹配原图：分层图 `TB`，左右流程 `LR`。
- 分组 = `subgraph`；**subgraph 声明顺序 = 层顺序**；**组内节点声明顺序 = 组内左右顺序**。
- **位置机制：每个节点的行位由「起点到它的最长路径长度」（rank）决定。** 位置错乱 = 路径长度不等：
  - 某节点缺少到下一层的连线 → 用不可见边补齐：`A ~~~ B`（三条波浪线，渲染无线条，但参与布局计算）。
  - 同层横向连线（如 网关→负载均衡、订单→支付）会给目标 +1 rank，把同组节点压到下一行，**不可见边拉不回来** → 回决策表改用 draw.io；若必须交 mermaid，渲染确认后明确注明「组内相对位置为近似」。
  - 分组框被拉成对角错位、无法堆叠成横带（dagre 分簇漂移）→ 代码首行加 `%%{init: {"layout": "elk"}}%%` 切 ELK 布局（v11 内置），可保住横带堆叠与组内顺序；同层横边的压行仍会存在。注意：init 指令若与 YAML frontmatter 同用，必须放在 frontmatter 之后，否则整个图解析失败。
- **迭代上限 2–3 次渲染**：默认布局发现问题 → 改代码或切 ELK → 再渲染 → 交付并注明近似。不要与布局引擎缠斗。
- 已验证陷阱：写在 subgraph 内的 `direction LR` 在成员有外部连线时被忽略，不要依赖它控制组内排列。
- 已知极限：subgraph 框宽度紧贴内容，无法强制为原图那种等宽全宽横带。
- 常见翻车：内容（组件/连线/标签）全对但行位错乱——基线测试中未渲染就交付，实际同层顺序颠倒、层间左右错位。

## PlantUML（用户指定时）

- `package` 嵌套表达分层，声明顺序影响排布；`together { }` 强制同组同行；`A -[hidden]- B` 补布局约束（官方 layout 手册技术）。
- 同为自动布局引擎，能力边界与 mermaid 相同：同层连线同样会扭曲位置。
- 时序图：`participant` 声明顺序 = 列顺序，稳定可靠。

## 常见错误

| 错误 | 后果 |
|---|---|
| 不渲染/不审查坐标就交付 | 位置错乱照常交付（最高频失败） |
| 只依赖声明顺序，路径长度不等 | 同层顺序被布局引擎重排 |
| 用 `direction LR` 钉有外部连线的 subgraph | 声明被忽略 |
| draw.io 全部 x=0,y=0 或随手坐标 | 打开后组件全部叠在一起 |
| draw.io 像素级测绘原图 | 花费 20 分钟换无意义的精度 |
| 与布局引擎无限缠斗 | 20 分钟挣扎换不来行位修复，2–3 次渲染上限 |
| 遗漏「组内左右顺序」对比项 | 库存/支付式互换，最难察觉 |
