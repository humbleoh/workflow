# Readability-Polish — 主题笔记段落修饰

修饰改「怎么写」，不改「写了什么」：把生硬的长句拆顺、读起来不必回看；缺因果处补推导衔接——但只展开本篇已有断言，不添新事实。断言、数字、术语、出处一字不动。产出 = 原文件就地编辑。

**先读规则文件** `riz-topic-note-rules/rules.md`（与本技能同处 `反刍/SKILLS/`）的 §5 行文契约——修饰的每一步都不得引入 §5 违规；修饰不是行文红线的豁免。

## 判定：什么句子要修

读到要回看才能找到主语或谓语的句子；定语套定语（「A 的 B 的 C」连排）；一句塞三个以上断言且无因果连接；读完不知道先发生什么后发生什么。**判据是「读者要不要回看」，不是句子字数**——已流畅的段落不动。

## 修饰手法（正面清单）

| 生硬特征 | 改法 |
| --- | --- |
| 一句多层：破折号 / 冒号 / 分号串三层 | 在语义边界断句，各句独立成立 |
| 因果 / 时序链挤在一句 | 流水句：子句按「因 → 果 → 果的后果」或动作先后排列，逗号衔接（先……，再……，最后……） |
| 定语嵌套（「A 的 B 的 C」） | 尾项单独成句，嵌套拆为两层陈述 |
| 名词化（「……的实现」「……的存在」） | 还原为动词句 |
| 被动句且施动者不重要 | 改主动，施动者信息不得丢 |
| 顿号长列举读起来赶 | 逗号分步（先……，再……），不追求句式工整 |

**流水句的边界**：一句流水句承载一条因果链，链上每个子句一个因果步——这是「因果显式」的实现，不违反规则 §5「短句直给」；互不依赖的并列断言不硬串成流水句，仍用短句。**衔接靠标点与既有连词（于是 / 因此 / 而），不新造过渡语**。

## 补全：衔接与因果（可补推导，不添新事实）

何时补：后句从前句推不出来（跳步）；「这 / 它」指代悬空；总起与分述不对账；因果链缺中间步，初学者接不上。

怎么补：

- 桥接句的原料**只能是本篇已有断言**：回指前文、把已有断言展开成推导步、补「于是 / 因此」类逻辑词。每补一句自查「这一步是本篇哪里说过的」，说不出来源就不补
- 给原文已有名词补白话同位注可以（如给符号补「（访问时间）」），注里不得带新断言
- 段内句序可调（服务因果链）；句子不跨段搬移

何时只报告不动：

- 断点需要本篇没有的事实才能接上——报告位置与所缺，交用户 / topic-note-reviewer
- 疑似笔误、用词不当（如「多数」疑为「多算」）——只报告，不代改
- 既有 §5 违规（加粗「推断」、破折号缺空格、填充语）——保留原样，报告；修饰不扩权修旧账

## 红线：一字不动物品

- **断言集合不变**：原文每条断言改后可寻、无一改动；新增句子只允许桥接推导句（见上节）——导语句、总括句、总结句、空过渡句仍一律不加
- **硬事实逐字不动**：数字、单位、频率、版本、型号、命令名、行内代码、$…$ 数学式
- **术语不动**：译名不改；「中文（English, Abbr）」首现格式不拆
- **链接不动**：URL / 锚点、显示文本、位置分型（句尾隐形 `[](url)` / 句中 `[§x](url)`）、`[[wikilink]]`、`<sub>…↗…</sub>` 旁注
- **取证标记不动**：「逐字：」「（逐字）」「逐字核自 X」「转引」「待考」「（推断）」「实测」——不移动位置、不改引入式（「逐字：」不得改「逐字写着：」）、不升为独立句；拆句时随其管辖的断言走
- **强调范围不拆**：`**粗体断言**` 整块留在一句内
- **结构不动**：标题、段落数量与顺序、表格、代码块、callout 类型与标题行、`> [!quote]` 引文块、前置阅读、references
- **填充语禁加**：「也就是说 / 可见 / 值得一提 / 总的来说 / 举例来说」类一概不加；关系已由标点承载处不补连词
- **文风红线依旧**（规则 §5）：无感叹号、无排比与抒情修辞、无修辞化动词

## 流程

1. 通读全文，按「判定」标出要修的句子——宁可多标，不漏长句最密集的段落
2. 逐段修饰；每段改完立即核对该段断言集合与红线
3. 全文改完，对照 diff 过一遍红线清单
4. 通读修饰后全文：是否流畅、有无引入新违规

**不动手只报告**：内容缺失、依据可疑、结构问题，以及上节「只报告不动」三项——记录位置与所缺，交用户 / topic-note-reviewer；修饰不处理这些。

## 常见错误

| 错误 | 纠正 |
| --- | --- |
| 加「本篇不讲 X」类导语句 | 新增句子 = 新增内容，只有桥接推导句可加 |
| 用「也就是说」「举例来说」补衔接 | 标点即衔接；加词即填充语 |
| 补桥时引入新事实、新机制 | 桥接原料限于本篇已有断言；接不上即报告 |
| 擅自换词消歧、纠错（「多数」→「多算」） | 用词属内容；疑似笔误只报告 |
| 代修既有违规（加粗「推断」、破折号缺空格） | 修饰不修旧账：保留原样，报告交 reviewer |
| 把句子跨段搬移凑衔接 | 只调段内句序 |
| 「（推断：…）」拆出成独立句、挪动出处括号 | 取证标记原地不动 |
| 「即换」改「就换」、「都动」改「都在动」 | 无可读性收益的微调不做，diff 面最小化 |
| 把列举改成排比对偶求「顺口」 | 排比是红线；列举改逗号分步，不加工整 |
| 最长的段落跳过没修（判为「本就是短句」） | 判据是「要不要回看」，最难段恰是修饰主目标 |
| 顺手改 callout、表格、references | 只修正文散文段；callout 正文散文可修，标题行与类型不动 |
