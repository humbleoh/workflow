# Topic-Note-Writer — 大纲条目笔记撰写

给定主题大纲中的一个条目，写出一篇**初学者可读**、符合 vault 契约的笔记。本技能只负责**流程**；所有写作判据（依据分级、结构骨架、深度契约、干货、行文、图片）都在共享规则文件中。

**先读规则文件**：`riz-topic-note-rules/rules.md`（与本技能、`topic-note-reviewer` 同处 `反刍/SKILLS/` 目录）。写正文时逐条遵守它的 §1 依据契约、§2 结构契约、§3 深度契约、§4 干货契约、§5 行文契约、§6 图片契约，交付前按 §7 合规清单自检。

流程四阶段：挖惯例 → 收依据 → 写正文 → 接线；交付前自检必须全过。

## 1. 分工

| 用户要的             | 用                    |
| ---------------- | -------------------- |
| 为大纲中某条目写一篇笔记     | **本技能**              |
| 为概念生成完整目录/大纲     | concept-toc          |
| 把既有概念归入 vault 结构 | concept-classify     |
| 审阅写好的笔记、反哺优化    | topic-note-reviewer  |

## 2. 阶段一：挖惯例（必做第一步）

按序读：
1. 主题的 `0. 大纲.md` 全文——目标条目名（中英）、**角色**（前置/原语/机制/惯用法/应用/综述）、一句话职责、所属章节；序列递进逻辑、范围边界声明与未覆盖登记。**据序列与边界声明定出本篇前置概念**：排在它之前的条目 + 边界点名的外部主题
2. ≥1 篇同主题已写笔记作结构模板，**优先同角色**（写惯用法就看已写的惯用法篇）；本主题尚无已写笔记时，取相邻主题一篇（如 `C++/并发编程/`、`Operating System 操作系统/实时调度 Real-Time Scheduling/`）
3. 条目的姊妹条目（同章相邻篇）——确认各自管辖面，避免重复

**机制本体单一**：若大纲条目名把两个独立概念并列（如「A 与 B」），先确认二者是否同一机制的两面；不是则提醒用户拆成两个条目——一篇笔记只承载一个可问答的机制本体（规则文件 §2），初学者分不清两个未展开概念的界限。

**标题不与姊妹篇同名**：机制本体在姊妹篇、本篇为应用/惯用法时，标题用动作/场景命名，不沿用机制名词、不与姊妹机制篇同名或为其子串（规则文件 §2）。

角色定重心：前置笔记回答「为什么需要它」并给对照基线；原语笔记给全控制面（身份、位置、设置/清除、效果清单）；机制笔记追问「怎么实现、边界在哪」（机制 + 边界 + 反例 + 证据）；惯用法笔记以「何时用、怎么写、怎么防误用」为中心，机制本体引回机制篇；应用笔记落一个完整方案，细节可转引；综述笔记给对照表与选型路径。**前置概念对所有角色成立**，不专属「前置」角色——读者是初学者，凡依赖未展开知识即须在开篇交代。**深度契约（规则文件 §3）亦对所有角色成立**：机制/原语篇讲清「为何这样设计」，惯用法/应用篇讲清「为何这样选」，综述篇讲清「为何演化成这样」。

## 3. 阶段二：收依据

依据分级（权威分级表）与全部内嵌规则见规则文件 §1（含：百科类仅作索引、不得作定义/语义首要依据；落「只做 N 件增量」「无新增断言」自述前须 grep 核对增量未被他篇覆盖、正文无越界断言）。此处只补三条流程约束：

- **预算：新增依据收集至多 6 轮工具调用**（如 2 次查文档 + 2 次实验 + 2 次补缺；下载图片、看图核对也计入）。到额即开始写作——不够的信息标「待考」，不是延长研究的理由
- **预算内优先级**：先核高价值项——机制本体 / 判据常量 > 触发条件 / 边界 / 反例 > 设计动机 / 历史成因 / 定值理由（末类取证成功率最低，一轮查不到即标「待考」，预算让位给前两类）
- **版本固定与同源核验**：非 RFC/标准类在线官方文档（指南页、博客页，可整页重写）上依赖页内具体示例或字节数的断言，收依据时即做本地实测兜底＋archive 锚或检索日期，不留到写正文时补；引书需要写章节号时，章节号与页锚同一次核验（先查目录再落笔），未核不写；PDF 页锚落笔前翻到锚页目检断言原文确在该页——原文与其相关表格/图分处两页时锚原文页（规则文件 §1.2）；RFC/标准引 HTML 锚点前核页面 `id` 实有该锚，无小节/分段锚时锚最近父级节、正文标记保留原引用号（规则文件 §1.2）
- **实测入文前重跑与分层标注**：行为类断言的底账须可原样重跑（完整命令＋关键输出摘录），断言写入正文前重跑一遍核对，修订回查时同样重跑（规则文件 §1.2）；引用 API/规范/库文档的契约句描述行为时注明断言所在层，具体工具/实现的行为以其实测为据、两者不互充（规则文件 §1.2）；正文点到在线语法表/参考条目的具体条目时，即决定实测或内联标「未实测」，不留中间态（规则文件 §1.2）
- **逐字引文摘录即标省略**：截取原文时以「…」标明省略处，插注/括注略去亦标注，底账与正文同规（规则文件 §1.2）

## 4. 阶段三：写正文

按规则文件 §2 结构契约的骨架写；深度、干货、行文、图片分别守 §3、§4、§5、§6。要点重申：认知顺序「最小例子 → 机制讲解（因果链显式成链 + 设计取舍）→ 边界与反例 → 速查」；凡有据断言，正文先说人话、出处按位置分型缀链接——句尾（句号/分号前、单元格末）隐形 `[](url#anchor)`，句中标记入链 `[§x](url#anchor)`，在线文档优先取带章节锚点的 HTML 版（库内 `[[笔记]]` 与 PDF 旁注同缀词后）；逐字引文留 references 底账——仅原文措辞本身承载断言（契约措辞、字面取值、歧义处）才入正文，已完整转述的断言不引，截取以「…」标省略，译文引语标「直译」或改转述；因果、设计取舍、历史成因三问讲透，查不到标「待考」，不凭常识编动机。**反例/失败模式自洽**（规则文件 §5）：反例、失败模式、选错后果示例涉及的沿、时序、状态位，以本篇定义表为基准逐沿核对，不得自相矛盾。

**示例、表格、图、速查是正文的兑现，不是平行材料**：
- 示例代码体现的规则与数字须与正文机制断言一致；正文规则修订后回查示例、其输出、及该数字在全文（对比句、速查表、references）的全部引用；接口/成员清单类背书逐项对到示例，未收成员就地显式声明，「输出正是动作序列」类背书中未逐一对应的输出行同样就地声明未收或就近给一句白话；需多个贯穿示例时逐一声明「全篇第 N 参照物」并各自沿用，禁止无声明混用（规则文件 §2）；官方例程摘录作参照物时，段级注释与空行按样板可删、删减面在块首注释声明，行数以官方原文口径计（自注声明行不计入），压缩用尽仍超域上限就如实计行并声明超限原因，不删守卫凑数（规则文件 §2）
- 命令行工具域的最小例子为「命令＋输出」代码块：参照物命令可进正文并声明，非参照物实验的完整命令仍归 references（规则文件 §2）
- 引本篇自身论证（正文、callout、表格一律）用实测编号或标题锚链接；「上文／下文／前述／下节」类方向词仅可作锚链接显示文本；段内加粗小标题不是合法锚目标，改用实测编号（规则文件 §2）
- 对照表依据格覆盖行内每条断言，跨篇依据同样以 `[[链接]]` 入格；引本篇自身论证用实测编号或标题锚，不裸指「上文/前述」（规则文件 §2）
- 图先于正文解释出现机制术语时，图内加括注或图后紧邻句补白话（规则文件 §6）
- 自绘图定稿前实际渲染核对；本机无渲染环境时改用 Mermaid（Obsidian 内建可当场核对）或委有环境的一步补核，核对记录写入 references 自绘条（规则文件 §6）
- 笔记自建的分层/分型框架，首句标明「本篇整理」，不以「通用结构分 N 层」类来源腔直陈（规则文件 §1.2）
- 机制归位/引走的路由目标对照大纲条目描述核对承载面，指向实际承载该机制的条目；机制分「语义本体＋某元素的配置位置」两层时并列双路由（规则文件 §2）
- 开放列举（规范原文有更多项）以「等」收尾并声明全表出处，不以无标记子集冒充完备（规则文件 §5）
- 速查表答案只改写正文已论证结论；新判据先在正文成段论证（证据＋买单方）再进表；答案格出处括注缀单元格末隐形链接或删去，无裸来源名（规则文件 §2）
- 吞吐/时长类实测数字标注随硬件性能变化、只作量级或倍数证据；译名先查库内既用（前置/姊妹篇），沿用或首现一句映射；缩写按豁免判据标全称（领域缩写标、CPU/URL 类通用缩写豁免）（规则文件 §5）
- 新概念、新参数、公式首现前先给动机句——它回应什么需求、缺它会怎样；机制的方向性命题（「携带」与「依赖对端已有」）写准，混说即学错（规则文件 §5 因果显式）
- 空链接 `[](url)` 紧贴前文不留空格；成对的对立术语（canonical / deterministic）各给一句成句定义；收束句直陈因果，不用对仗杂糅比喻（规则文件 §5）
- 行内调用呈现统一：函数名与实参同入代码段、括号前空格与参照代码一致，不把实参悬在代码段外；同一标识符全文同形态（规则文件 §5）

## 5. 阶段四：接线

1. 在 `0. 大纲.md` 中把本条目 `*(TODO)* 条目名` 替换为 `[[完整条目名|短条目名]]`，角色与职责描述原样保留
2. 新增或重定向 ≥1 条入链：既有笔记/相邻大纲若已指向本主题，更新为直指新笔记（更精确时）；姊妹笔记关系表中已预留本篇 TODO 的，顺手补链
3. 正文、前置阅读与关系表中的未写条目 TODO 统一带章节号（如 `（TODO 待落地，一.3.5）`）

## 6. 交付前自检（任一不过，修完再交）

先逐条过规则文件 §7 合规清单，再补两条交付项：

- [ ] 文件名 = 条目名；大纲 TODO 已更新；入链 ≥1
- [ ] 全文无「删掉也不影响决策」的空话（干货反判据，见规则文件 §4）

## 常见错误

| 错误                | 纠正                                                   |
| ----------------- | ---------------------------------------------------- |
| 「这我知道」，凭记忆直接写     | 记忆不是依据；查文档/跑实验/找实录，自检第 1 条会拦截                        |
| 论坛见过的结论，凭印象复述     | 社区实测可作 2 级依据，但必须给链接；找不到就标「待考」                        |
| 无限追查来源，迟迟不动笔      | 6 轮预算（转引不占）；到额用现有材料写，缺口标「待考」                         |
| 来源打不开就绕开不写        | 标「转引/待考」+ `> [!info]` 说明获取状态——诚实降级，不是省略              |
| 参数选项面面俱到、堆成手册     | 角色定重心：机制笔记追机制与边界，不做手册拷贝                              |
| 笔记之间内容重叠、各说一遍     | 开篇边界声明：本体归机制/原语篇，本篇只答自己角色的那个问题，其余 `[[引走]]`           |
| 前置概念没交代，读者卡在半路    | 开篇 `> [!info] 前置阅读` 列已写前置；未写的正文首现给最小定义               |
| 表格只给结论            | 关键断言表加「依据」列——结论与证据同格                                 |
| 网上抓图不打开就用         | 必须看图核对——图文不符比没图更误导                                   |
| 图随手存、用默认时间戳名      | 统一存 vault 根 `pictures/`，描述性中文命名，正文 `![[文件名.png]]` 引用 |
| 为配图而配图            | 图是表达工具：文字说不清时才用；一篇 0–5 张                             |
| 官方无现成图就硬凑旧图或弃图    | 可自绘或委派多模态模型：SVG / Mermaid / 脚本生成；图中只放正文已核实的断言                |
| references 罗列正文已内嵌的来源 | references 只留附录：本地实验底账 + 逐字引文底账 + 离线来源 + 待考清单 + 图片出处，已内嵌来源不重复                            |
| 用「(4.3 实核)」这类标记代替链接 | 依据内嵌正文：断言＋句尾 `[](URL)` / `[[笔记]]`，`§章节` 紧随其后，不留孤立标记 |
| 正文甩英文原句当论据 | 先说人话＋句尾缀链接；逐字底账进 references，确需逐字先给中文引入 |
| 软件域实测把完整命令连参数抄进正文场景 | 正文留「动作 → 所见 → 数字」，完整命令入 references 本地实验条目；CLI 工具域的参照物命令＋输出可进正文并声明（规则文件 §2） |
| gst-launch、Ogg 类名字裸奔出现 | 首现处一句白话：谁制定、是什么、干什么用 |
| 待考/推断在正文加粗打断 | 取证状态内联不加粗；链接与断言是正文主角，取证是旁注      |
| 笔记写完，大纲条目还是 TODO  | 接线是「写完」的一部分，不是可选项                                    |
| 例子跑不通 / 注释与实际输出不符 | 自检第 3 条；未验证的例子宁可删                                    |
| 只给结论，不给因果         | 因果链显式成链（深度契约）；删掉中间环节读者能否补上？不能即未讲透                     |
| 总起句「A 带来 N 个问题」，分论点前提各不相同 | 总起对账：前提不同源就并列各表前提；虚假归因比无总起更误导 |
| 用被定义词定义术语（拿「对象实例」解释「对象」） | 从内存/机制层给非循环定义 |
| 「一件东西」「两笔代价」类概称无先行词 | 首现处点名映射对象，后文方可复用 |
| 只讲「它是这样」，不讲「为何不是那样」 | 给备选做法与代价（设计取舍）；不做对比不算讲透                               |
| 把怪设计当成理所当然        | 查历史成因与兼容包袱；查不到标「待考」，不编                                |
| 凭常识替设计师编动机        | 动机须引官方理由；推断注明「（推断）」并给理由                               |
| 辞藻修辞、抒情过渡、「钉死 / 摆齐」类修辞化动词凑篇幅 | 朴实高密度：直陈事实，改用「定义 / 并列 / 体现 / 区分」等直陈动词 |
| 干货 = 参数罗列          | 反判据：删掉它读者做决策会不会错？不会 → 删                |
| 手头有书仍引幻灯片/转述外链     | 经 pdf 工具定位核对后引 `[[books/x.pdf#page=N\|⧉]]`；书里没有的内容保留原出处     |
| 要点是速记片段，初学者跟不上    | 成段展开：主张 → 现实/机制 → 后果与应对；条目清单只是草稿骨架      |
| 一词多义不拆维度直接举例      | 先显式列出术语混含的几件事（维度），再让例子逐维度对号入座         |
| 段落以「先明确两个指称」类答句腔开写 | 叙述体成文：从上文自然引出对象再下定义，上下文由正文自己给 |
| 「类别一串、元素一串」两串裸列称「对应」 | 对照表逐行或句中成对点名「谁对谁、各自行使什么」 |
| 正文写「本机 / 本地」类个人视角词 | 环境中性表述（「GStreamer 1.28.2 实测」），环境与命令底账在 references |
| 「这个闭环」类牵强概称词 | 直呼其物（「这个最小例子」）；修辞化名词与「钉死/摆齐」同罪 |
| 出处写成「（[send(2)](URL)）」带名括弧式 | 链接按位置分型：句尾隐形 `[](url#anchor)`、句中 `[§x](url#anchor)`；在线文档取带锚点 HTML 版；PDF 旁注用 `<sub>…↗…</sub>`（规则文件 §1.2） |
| 「逐字引自」入 quote 标题、「逐字：」入正文 | callout 类型已表明逐字，标题只给出处；行内原文用「原文：」 |
| 示例调用凭空出现（正文突然冒出 `append`） | 首次使用前先立最小场景并声明为全篇参照物；正文、图、速查统一同一示例名（规则文件 §2） |
| 「先立一个最小场景：」类口号式开头 | 场景直接从事写起，不喊写作动作（规则文件 §2） |
| 「X 点破 / X 的评语是…」转述评语 | 判断直接成文，出处只留页锚（规则文件 §5 不借他人评语立论） |
