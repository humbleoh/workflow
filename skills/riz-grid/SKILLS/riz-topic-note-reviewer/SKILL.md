# Topic-Note-Reviewer — 笔记审阅与反哺

审阅一篇按共享规则写成的主题笔记，产出**问题清单**，并区分两类发现：**内容违规**（笔记违反某条现行规则，修笔记）与**规则缺口**（笔记未违反任何现行规则却仍卡住读者/学不到东西——规则或写作技能缺一条，反哺优化 `topic-note-writer`）。

**先读规则文件**：`riz-topic-note-rules/rules.md`（与本技能、`topic-note-writer` 同处 `反刍/SKILLS/` 目录）。审阅的唯一判据就是这份规则文件；不另立标准，不按个人文风偏好扣分。

审阅的唯一产出是问题清单，不是改写稿、不是最佳实践讲座、不是文字润色。

**收录判据**：这条问题不修，读者会**卡住**（无法继续）或**学错**（形成错误理解），或**违反规则文件某条判据**吗？不会 → 不收录。

## 读者画像

有一定基础的初学者：懂基础概念和语法，缺实践经验、体系理解、排错能力。不需要解释「什么是变量」「什么是命令行」；需要：每个结论怎么来的、每个新概念从哪来、每条依据是否查得到。

## 审阅方法：对照规则 + 模拟执行

分两遍：

1. **逐条对照规则文件**：按 §1 依据契约 → §2 结构契约 → §3 深度契约 → §4 干货契约 → §5 行文契约 → §6 图片契约 → §7 合规清单，逐条检查笔记是否达标。凡违反任一条即记下，标注违反的是哪一条。
2. **模拟读者执行**：把自己当成上述初学者，从头到尾读一遍——每个新概念前文有铺垫吗？每个结论能顺着「因为 → 所以」自己补上吗？每个断言链到来源吗？读到哪里会犹豫、会卡住、会想「为什么」而文中没答？全部记下。

两遍合并，按「规则」归位。无法实际运行时，至少纸面推演：检查断言的可追溯性、因果链的完整度、术语的一致性。

**抽核**：对最重要的断言（机制本体、判据常量）抽核 1–2 处——链接是否真的指向所述内容。错链、断链、链接指向与断言不符 = 高严重度（「可溯源」是契约，不是形式）。

## 检查维度（对应规则文件）

1. **依据 §1**：断言可溯源且不打断（链接精确度与**位置分型**：句尾隐形 `[](url#anchor)`、句中标记入链 `[§x](url#anchor)`，无「`[](URL)` 后缀裸 `§x`」旧式；空链接紧贴前文、无标点前悬空空格；RFC 等在线文档取带章节锚点的 HTML 版且**锚点实核可达**，无小节锚时锚最近父级节；**转述保真**不放大范围——组件/协议承载的断言未写成整个装置；电子书页锚、诚实标记、穷举断言、为何类取证、版本标注）；凭记忆落笔、裸结论、错链
2. **结构 §2**：骨架齐全（标题/开篇定义/前置阅读/动机/定义与机制/关系/相关笔记/references）；边界声明（与姊妹条目有重叠面时）；前置概念交代；最小例子；速查
3. **深度 §3**：因果链显式成链（删掉中间环节读者能否补上）、新概念/公式首现前有动机句（凭空掉落即卡点）、机制方向性命题（携带 / 依赖对端已有）未混说、设计取舍给了备选与代价（落到设计决定 + 证据 + 买单方）、历史成因讲明来源；无据处标「待考」，未凭常识编动机
4. **干货 §4**：关键量化事实（阈值/公式/量级）+ 至少一条反直觉结论或生产坑；无「删掉也不影响决策」的空话
5. **行文 §5**：朴实高密度、叙述体成文、总起对账（按层/逐项承诺代价时逐层点名承接，原书未标的项有交代）、概称词点名、定义无循环、对应逐对点明、术语译名准确（用标准译名不意译）、缩写首现标全称、工具名首现有白话注解、机制性术语与成对对立术语有成句定义、待考内联不加粗；破折号「——」前后留空格；无「X 点破 / X 评语是 / 官方那句 / 写得更直接」类转述评语；同句不重复点名；专有名词先定义后使用；解释性依托概念首现有 wikilink；贯穿示例（正文/图/速查）同名；收束句直陈、无对仗杂糅；自建分类附分类轴白话
6. **图片 §6**：图文一致、无重叠截断、图与正文断言一一对应、描述性命名、出处/依据已入 references；能映成对照表的分类不用图；删图后 references 无孤儿底账

## 严重度定义（排序依据）

| 级 | 定义 | 典型特征 |
| --- | --- | --- |
| 高 | 违反核心契约：照做**必然失败**或形成错误结论 | 断言不可溯源/错链；因果链断（中间环节删了读者补不上）；按常识编动机；代码块跑不通；干货缺失到决策会错 |
| 中 | **卡住需外部求助**，或会形成错误理解 | 前置概念未交代；术语/工具名裸奔；概称无先行词；边界未声明；术语与本体错位 |
| 低 | 能走完，但绕路 / 读起来费力 / 不严谨 | 行文啰嗦、填充语；待考未标；表格裸来源；图未核对；references 重复罗列已内嵌来源 |

## 输出契约

评审结果 = **最多 8 条**问题，按严重度高→中→低排序，输出前不加总体评价、不附全文改写稿。每条：

```markdown
### N.〔高｜中｜低〕一句话问题标题

- **位置**：章节/段落，引用原文关键短语定位
- **规则**：违反 rules.md 哪一条（§X 或具体条目），或标「规则缺口」
- **类别**：内容违规 | 规则缺口
- **读者状态**：他刚读到什么 → 卡在哪一步。必须写成具体动作序列
  （如「读到『零空周期』，不知道它为何导致降档，往前翻没有解释」），
  禁止写成「读者可能感到困惑」式抽象形容
- **改法**：内容违规给最小修改片段，可直接执行；规则缺口给反哺建议——
  说明应在 `topic-note-writer` 或 rules.md 增加什么规则堵住这个洞
```

不足 8 条就少列；琐碎问题合并进相邻条目；全文确实没有问题就明说没有，不硬凑。

**文末「反哺摘要」**：汇总所有「规则缺口」条，逐条给出一条「应在规则文件/写作技能增加什么」的建议。这是本技能对 `topic-note-writer` 的反馈通道——不改文件，只列建议，由人工或另行执行。

## 常见错误

| 错误 | 纠正 |
| --- | --- |
| 把审阅做成润色/文风点评 | 判据只有 rules.md；不是规则违规、不卡读者、不学错 → 不收 |
| 列 10+ 条流水账 | 契约上限 8 条：先按收录判据砍，再合并同类 |
| 「读者可能困惑/迷失」式抽象描述 | 读者状态必须是动作序列：读到什么 → 卡在哪/看到什么 |
| 把规则缺口当内容违规（或反之） | 规则缺口 = 笔记没违反现行规则却仍有问题；先对照 rules.md 判有无对应条目 |
| 只查行文不查依据/深度 | 依据可溯源与深度契约是核心契约，漏掉它们等于没审 |
| 先写总体好评再列问题 | 输出只有问题清单，无开场评语 |
| 按文章行文顺序罗列 | 按严重度高→中→低排序 |
| 附整篇改写稿/重写代码 | 只给最小修改片段 |
| 反哺建议写成「加强 XX 意识」式空话 | 反哺建议必须落到「增加一条什么规则」，可执行的 |
| 凭印象断言「这条违反规则」 | 引用 rules.md 具体条目（§X），并指认笔记原文定位 |
