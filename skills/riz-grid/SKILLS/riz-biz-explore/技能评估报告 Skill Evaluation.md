# 技能评估报告 Skill Evaluation（riz-biz-explore）

**评估对象**：`反刍/SKILLS/riz-biz-explore/SKILL.md`
**方式与日期**：2026-09-17。Oracle agent 主评（对照 9 大成熟框架 + writing-skills 技能编写标准）；编排者已逐条核对报告中的行号引文与技能原文（全部吻合），框架断言与带源基准 [[商业机会评估框架基准 Business Opportunity Frameworks]] 交叉比对无矛盾。
**结论**：8 / 10（B+）。

## 1. 总评

**综合评分：8 / 10（B+）**。工件质量（维度 a）8.5 分：结构、证据分级、可证伪性约束、反空泛规则在同类 prompt 级商业分析技能里属上乘，与 vault 兄弟技能生态高度一致；扣分在触发词过宽、描述摘要了方法论（writing-skills SDO 明确禁止）、打分机制欠规格且有「六维 vs 八维」内部矛盾（L116 vs L72–79）。方法论质量（维度 b）7.5 分：以「闭环四段」重构后实际覆盖了 Business Model Canvas 约七成模块，飞轮、杠杆两个概念的使用比常见误用更严格；但存在一个结构性方向倒置——从技术出发找场景（solution-first），与 Customer Development / Lean Startup 的问题优先原则相逆，且「手搓 = 付费意愿证据」（L35）是全文最危险的一处推理越界。

**范围声明**：本技能定位是「探索/评估」而非创业执行。pivot/persevere、innovation accounting、融资、TAM 测算等属执行阶段或按设计排除的内容（L47「资本杠杆默认不写」），不罚分；但「验证交接」（分析结论→下一步最廉证伪动作）属评估阶段合理延伸，缺席记为缺口。

## 2. 优点

1. **证据分级 + 强制联网，直接反「凭感觉的市场分析」**。L87–97 四级来源表（L89「官方定价页、官方文档、一手实测」为一级）+ L97「**必须联网调研**（websearch / librarian），禁止凭记忆报价格、报竞品」+ L96「矛盾数据必须显式裁决」。这是对 hallucination 邀请的结构性防御，方法论上呼应 writing-topic-notes 的权威分级（L85 自注「仿 writing-topic-notes」），也符合 Lean Startup「validated learning 要求证据而非观点」的精神。
2. **可证伪性机制罕见地严格**。飞轮：L41「写不出『资产 + 降低机制』两条，就必须判『无飞轮』」；原型：L57「需自研底层算法/协议……明确判『3 个月做不出』，不画饼」；需求：L35「写不出这个门槛 = 需求是猜的」。三条硬判据让分析产出「否决」而非只产出「可能」。
3. **飞轮用法规避了最常见的误用**。L39「飞轮 ≠ 口碑；口碑是结果，不是机制」直接挡住了 Collins《Good to Great》飞轮概念最常见的滥用（画一个圆圈即称飞轮）；L40 要求点名「累积资产 + 降低机制」，且 L41 承认「单人工具通常无飞轮」——对 ex ante 分析而言，允许判「无」比强编一个飞轮更诚实（Collins 原意中飞轮是事后从经营数据中发现的动量）。
4. **反空泛获客，把渠道做成硬约束**。L33「获客段必须具体……禁止『内容营销 / SEO / 社交媒体』这类空泛词」+ §3.5（L61–64）要求「具体渠道 + 可执行动作（如『在 X 社区搜痛点原话 → 回复方案 → DM 免费帮搭』）」。这是 indie-hacker 社区 distribution-first 思维的正确落地，也把 BMC 的 Channels 模块从名词变成了动作。
5. **「一人公司」是贯穿性硬约束而非口号**。L34 可变成本趋零 + 具体数字示例（「PartyKit $5–20/月」）；L47 排除资本杠杆；L73「一人可交付」入排序判据。与 Naval 杠杆框架中 permissionless（code/media）优先、permissioned（capital/labor）受限的划分逻辑一致。
6. **闭环四段 = BMC 的运营化改写**。L31–32「获客 → 交付 → 收费 → 留存/复购」逐段标「谁来执行、耗时、单客成本」——把 Osterwalder 的静态九格改造成了一人公司视角的单位经济流水，且 L65 收费路径「一次性『接入 + 定制』价 → 转月费」符合中小企业采购现实与 indie 圈「monetize early」（Pieter Levels）信条。
7. **§7 常见错误表（12 行）即 writing-skills 所倡导的 rationalization table**。如 L111「凭记忆报价 = 违规」、L113「写不出就判『无飞轮』」、L117「全程只讲技术不讲钱 → 要写出成本结构数字」。这是对「技能防杠化」标准（writing-skills「Build Rationalization Table」节）的忠实执行。
8. **用户检查点与零副作用设计**。L8「先对话输出，用户确认后才写 vault」、§6 标题即「仅在用户确认后；确认前零写入」、L25 落地询问压缩为一句话。与 concept-toc §4、concept-classify 的确认门惯例完全一致，生态一致性好。
9. **分工表与自行裁定**（L12–17、L20「不盘问用户，自行裁定并明说」）复刻了 concept-toc 的 §0 模式，避免了分析前的盘问摩擦。

## 4. 缺口与盲点（按危害排序）

1. **【高】方向倒置：从技术出发找场景（solution-first）**。§2 第 2 部分（L21）「这技术能用在哪些场景」——入口向量是技术推场景。Customer Development 与 Lean Startup 的第一原则是问题优先：任何技术总能找到*某个*似是而非的场景，tech-first 枚举天然邀请动机推理，评分时的「需求真实性」可能被弱手搓证据回填。技能自己的解药（L35 门槛、L33 反空泛）存在但只在这一方向上事后设卡，没有翻转方向本身。
2. **【高】「手搓 = 需求已验证 = 付费意愿证据」（L35）推理越界**。手搓证明**问题存在**，不证明**付费意愿**——用户可能永远容忍 Excel；Mom Test 的金标准是「过去为解决方案花过的钱/行为承诺」。这条等式一旦被代理照抄，会产出全文最危险的一类假阳性：「需求已验证」。L41 对飞轮做到了「写不出就判无」，对付费意愿却没有同等严格的分级。
3. **【高】无验证交接**。分析止于排序清单；L56 的 3 个月里程碑是纯构建里程碑（「第 1/2/3 个月各做什么」以做出 demo 为目标），没有把任何一个月转为「进社区谈 N 个用户 / pre-sale 收订金」类最廉证伪动作，也没有「下一步验证清单」输出。Lean Startup 的 build-measure-learn 中「measure/learn」半环缺失——评估技能至少应交付「每个头部方向的最便宜证伪实验」。这正是「无需求证据就开建」风险的残留通道。
4. **【中高】媒体/受众杠杆缺位**。Naval 四分法中 code **和 media** 是仅有的两种 permissionless 杠杆；indie 圈（Levels 等）实践中 audience-first 常是一人生意的第一杠杆。L46 的四类（技术/平台/网络/时间）漏掉 media；且 L33「禁止『内容营销 / SEO / 社交媒体』这类空泛词」若被字面理解会进一步排除内容渠道（该条本意是禁空泛措辞而非禁渠道，见执行风险 6）。
5. **【中】「竞品空白」单向计分**。L77 只问「大厂/免费品是否已覆盖」，把竞争 presence 仅作减分项；不提示「无竞品可能 = 无市场」（Blank/Ries 传统中竞品是需求的存在性证明），也不问 Thiel 式差异化/防御（「为什么大厂或另一个 indie 三个月吃不掉你」）。按现表打分，代理会犯「零竞品 = 满分」的新手错误。
6. **【中】打分机制欠规格 + 内部矛盾**。§4（L68–81）定义了 8 个维度但无分制（0–2？1–5？二元？）、无权重、无聚合规则，产出不可复现；且 L116 写「§4 **六维**打分」与 L72–79 实际 **8 维**自相矛盾，代理无从判断哪个是权威集合。
7. **【中低】市场类型缺席**。Blank 的 market type（新市场/现有市场/细分重组）直接改变获客经济学（新市场需教育、现有市场拼差异化）；范围裁定（L20）加一行即可覆盖，现缺。
8. **【低】定价方法薄**。仅 L65 路径启发式，无价值锚点/成本底线逻辑。评估阶段可接受，降为低。
9. **【范围外，不罚分】**：TAM 测算（一人公司做 niche 反而是理性选择，Levels 亦主张不为 TAM 焦虑）、pivot/persevere 与 innovation accounting（执行阶段）、融资（L47 明确排除）。

## 5. 执行风险（LLM-agent 失败模式，溯源到具体章节）

1. **触发误击**：L3 触发词含 `'MVP'`、`'prototype'`、`'原型'`、`'技术难度'`、`'获客'`。本 vault 是开发型环境，"MVP" 常指 Model-View-Presenter、"评估这个重构的技术难度"、"做个 prototype" 是纯开发请求——技能会误触发起商业分析。§1 分工表（L12–17）只对兄弟 vault 技能设界，未对开发类任务设界。
2. **SDO 陷阱**：L3 描述写明「built around three pillars: 商业闭环…飞轮效应…杠杆」——摘要了方法论。writing-skills「SDO」节明确记载：描述一旦摘要 workflow，代理可能照描述做一次浅层三视角分析而不读正文（正文中的证据分级、反空泛规则被跳过）。
3. **研究循环无界**：L97 强制联网调研，但全文无工具调用预算或停止条件。对照 writing-topic-notes L44「至多 7 轮工具调用……到额即开始写作」，本技能会导致两极失败：过度研究（无限 websearch）或一轮即宣称合规。
4. **伪精确打分**：§4 无分制与锚点（缺口 6），代理会自造「8.5/10」式数字，恰好违背 L8 核心原则「商机是分析出来的，不是罗列出来的」的精神——用数字罗列冒充分析。
5. **数字压力下的编造**：L34 要求成本「写出具体数字（如 PartyKit $5–20/月）」+ L89 要求定价断言给链接；若 websearch 受阻，具体数字的压力邀请编造。§5 的「待考（加粗）」（L95）是部分兜底，但没有 writing-topic-notes L43 那样显式的「来源不可达 → 诚实降级标记」协议。
6. **禁令过度执行**：L33/L66 的排除措辞（「禁止『内容营销 / SEO / 社交媒体』」；L66 排除 Product Hunt 首发）是「禁空泛措辞/禁低转化动作，除非有反例证据」，但字面代理可能读成「这些渠道一律不得提议」，放大缺口 4。
7. **假阳性需求验证**：L35 的定义性等式（「手搓 = 需求已验证 = 付费意愿证据」）被代理照抄后，任何 Excel 变通方案都会被升格为「已验证」——这正是该技能最想防的失败，却由自身定义诱发（缺口 2）。
8. **末点检查与整轮浪费**：唯一用户检查点是 L25（六部分全部产出后）。L20 允许代理自行裁定范围，若裁定偏了（技术歧义、细分选错），整轮联网研究+六部分分析全部作废；与兄弟技能一致（concept-toc 同模式），但兄弟技能不涉及多轮联网研究，本技能的浪费成本更高。
9. **（工件层面，无法从文件验证）**：writing-skills 的 Iron Law 要求技能先有失败基线测试；本技能的常见错误表显示作者预判过失败模式，但工件中无基线测试记录，是否执行过 RED-GREEN 流程不可考——仅记录，不定罪。

## 6. 改进建议（P0/P1/P2，均可溯源到上文缺口/风险）

**P0（修错与止血）**

1. **§4 + L116：补打分规格，修内部矛盾**。给每维定二元/三级分制与聚合规则；建议把「需求真实性」与「获客可及性」设为**一票否决门**而非加权平均（需求或渠道为零的方向不应被其他维度平均救活——indie 实践中这两项失败不可补偿）；L116「六维」改为「八维」。→ 缺口 6 / 风险 4。
2. **L35：把验证门槛拆成两级**。「问题存在（手搓证据）」与「付费意愿（已在为替代方案花钱/预算/岗位存在的证据）」分开判；措辞从「需求已验证」降为「问题有据 / 付费待验」，找不到后者时强制标注**待考**——与 L95 现有机制对齐。→ 缺口 2 / 风险 7。
3. **§2 第 2 部分：加独立需求侧证据要求**。每簇「真实痛点」必须附 ≥2–3 条带链接的用户原话（来自 L63 所指的具体社区），先有痛点再有技术匹配，翻转 tech-first 方向。→ 缺口 1（兼缓解风险 5 的编造压力）。

**P1（方法论补强）**

4. **§3.3：增设「媒体/受众杠杆」**（内容/受众/分发资产，Naval 的 media；含 build in public），并同步微调 L33 措辞为「内容类渠道必须给具体动作与量化依据」而非「禁止」句式。→ 缺口 4 / 风险 6。
5. **§3.4：第 1 个月里程碑改为验证里程碑**（进社区/访谈/pre-sale），并在输出契约第 5 部分后追加「每个头部方向的一条最廉证伪实验」——补上 Lean Startup 的 measure/learn 半环。→ 缺口 3。
6. **§4 L77：「竞品空白」改写为「竞争格局」**：竞品存在 = 需求佐证 + 差异化空间 + 「大厂/另一个 indie 为何 3 个月内吃不掉你」。→ 缺口 5（Thiel 防御性 + 反「零竞品即满分」）。
7. **§5：加研究预算与不可得协议**。仿 writing-topic-notes L44 定「至多 N 轮工具调用，到额即写，缺口标待考」；补「来源不可达 → `>[!info]` 诚实标记」条款。→ 风险 3 / 风险 5。

**P2（工件与生态打磨）**
