# Riz-Biz-Explore — 技术的商机与前景探索

给定一个技术，从「一人公司」视角探索它的应用前景与商机。核心原则：**商机是分析出来的，不是罗列出来的**——三视角（闭环 → 飞轮 → 杠杆）必须逐一推导、可证伪，每条断言带证据分级；先对话输出，用户确认后才写 vault。

## 1. 分工

| 用户要的 | 用 |
| --- | --- |
| 探索一个技术的**商机与前景**（一人公司视角） | **本技能** |
| 为概念生成完整目录/大纲 | concept-toc |
| 把既有概念归入 vault 结构 | concept-classify |

## 2. 输出契约（分析阶段，六部分按序，缺一不可）

1. **范围裁定**：一句话锁定技术是什么（含它不包含的相近技术）、本次聚焦哪个细分。不盘问用户，自行裁定并明说。
2. **应用前景**：这技术能用在哪些场景，按需分 2–5 簇。每簇给：场景名、真实痛点、谁在用/谁在要（证据）。
3. **技术难度与原型可行性**：评估学习/集成难度，判断一人能否 1–3 个月做出可 demo 原型，给 3 个月里程碑（见 §3.4）。
4. **三视角分析**：闭环 → 飞轮 → 杠杆，逐一推导（见 §3）。
5. **商机排序**：由三视角收敛出的候选方向，按统一判据打分排序（见 §4）。
6. **落地询问**：仅一句话——问用户「是否按 §6 写入 vault？」，位置提议属 §6 确认后工作，不得提前产出。

## 3. 三视角分析框架（核心）

### 3.1 商业闭环

- **定义**：一段「获客 → 交付 → 收费 → 留存/复购」的完整循环，钱进 > 钱出，且每一环都能由**一人**完成、不依赖持续投入创始人的稀缺时间。
- **推导要求**：画出闭环四段，逐段标「谁来执行、耗时、单客成本」。
- **获客段必须具体**：回答「第一个付费客户从哪来」——具体渠道名 + 一句可执行动作（见 §3.5）。禁止「内容营销 / SEO / 社交媒体」这类空泛词。
- **成本结构**：固定成本（我的时间）与可变成本（infra/托管）各多少？一人公司的优势在可变成本趋零，local-first / 托管基建恰好满足——要写出具体数字（如 PartyKit $5–20/月）。
- **验证门槛**：目标场景现在是否在「手搓」（Excel / 微信 / 纸质）？手搓 = 需求已验证 = 付费意愿证据。写不出这个门槛 = 需求是猜的。

### 3.2 飞轮效应

- **定义**：自我强化的循环，每一圈**降低下一圈的边际成本**。飞轮 ≠ 口碑；口碑是结果，不是机制。
- **推导要求**：点名「累积资产」是什么（数据 / 网络 / 模板库 / 社区），再点名「降低机制」——这资产如何让下一圈获客或交付更便宜。
- **可证伪判据**：单人工具通常无飞轮（无网络，用户不增长）；协作/平台型产品才有网络飞轮。**写不出「资产 + 降低机制」两条，就必须判「无飞轮」**，不得含糊说"能形成飞轮"。

### 3.3 杠杆（以技术为支点）

- **定义**：杠杆 = 产出 / 自身投入。一人公司的杠杆 = 让「别人/系统的资源」替你出力。**支点** = 该技术本身的什么特性；**动力** = 谁/什么在替你出力。
- **杠杆类型**（逐条判断是否命中，命中才写）：技术杠杆（build once, sell many）、平台杠杆（寄生 Cloudflare/Vercel/App Store 分发）、网络杠杆（用户拉用户，协作产品天然 viral）、时间杠杆（自动化 / AI agent 替你做交付）。
- **排除**：资本杠杆（融资）默认不写，除非用户明确有资金。
- **每条杠杆必须写：支点（技术特性）+ 动力（外部资源）**，缺一不可。

### 3.4 技术难度与原型可行性

- **定义**：评估该技术的学习曲线、集成难度与生态成熟度，判断一人能否在 **1–3 个月**内做出可 demo 的原型（MVP）。
- **推导要求**：
  - 技术难度分级：调库拼装（几天）/ 需深入理解（数周）/ 需自研底层（数月，一人公司红灯）。
  - 生态成熟度：有无现成 SDK / 开源库 / 托管服务 / 教程？成熟度高 = 原型快。
  - 给出**3 个月里程碑**（第 1/2/3 个月各做什么），而非一句「能做」。
- **红线**：需自研底层算法/协议、或依赖尚未稳定 API 的技术 → 明确判「3 个月做不出」，不画饼。

### 3.5 获客路径（第一个付费客户）

- **定义**：回答「第一个付费客户从哪来」，给**具体渠道 + 可执行动作**，而非获客理念。
- **推导要求**：
  - 目标客户聚集在哪（具体社区名 / 平台 / 论坛）？
  - 一句可执行动作（如「在 X 社区搜痛点原话 → 回复方案 → DM 免费帮搭」）。
  - 收费路径：一次性「接入 + 定制」价 → 转月费，比一上来卖订阅更符合中小企业决策。
- **排除**：冷邮件 / DM 群发 / Product Hunt 首发（一人公司转化率≈0），除非有反例证据。

## 4. 商机排序判据（统一维度，逐项打分）

| 维度 | 问 |
| --- | --- |
| 需求真实性 | 手搓证据？还是猜的？ |
| 一人可交付 | 能一个人做出来并维护？ |
| 成本结构 | 可变成本能趋零？ |
| 飞轮 | 有无「资产 + 降低机制」？ |
| 杠杆 | 命中几条杠杆？ |
| 竞品空白 | 大厂/免费品是否已覆盖？ |
| 技术可行性 | 1–3 月能做出可 demo 原型？ |
| 获客可及性 | 第一个付费客户的渠道找得到？ |

候选方向给一句「为什么一人能做」（技术解决哪段，剩下的是你对行业的理解），而非叙事长文。

## 5. 证据分级（所有断言必须带级）

市场数据分级，仿 writing-topic-notes 的权威分级：

| 级 | 来源 | 用法 |
| --- | --- | --- |
| 1 | 官方定价页、官方文档、一手实测 | 定价与功能断言的首要依据，给链接 |
| 2 | 竞品官网、官方公告、官方博客 | 竞品能力与定位依据 |
| 3 | 权威二手（G2、行业报告、知名媒体） | 辅助，标「编辑性概述」 |
| 4 | 博客 / 论坛 / Reddit / 推测 | 仅取需求信号与直觉，不作定价依据 |

规则：
- 每条断言标注：**出处**（链接）/ **推断**（给理由）/ **待考**（加粗）。
- **矛盾数据必须显式裁决**：如两处来源定价不一致，写「两处不一致，取官方现价 X，另一处为历史/旧定价」，不得静默丢弃。
- **必须联网调研**（websearch / librarian），禁止凭记忆报价格、报竞品。

## 6. 落地阶段（仅在用户确认后；确认前零写入）

1. **位置裁定**（向用户提议并获批）：`反刍/` vault 下合适目录（如 `工作/` 或新建 `商机/`），遵循 vault 中英并列命名惯例。
2. **落库格式**：分析正文转成笔记骨架——`# 标题` + 开篇一句话结论 + `## 应用前景` + `## 技术难度与原型可行性` + `## 商业闭环` + `## 飞轮` + `## 杠杆` + `## 商机排序` + `>[!references]`（按证据分级列出，每条注明支撑了哪条断言）。
3. **接线**：在相关既有笔记补至少 1 条指向新笔记的链接。
4. **校验后汇报**：落库路径、结构变更点。

## 7. 常见错误

| 错误 | 纠正 |
| --- | --- |
| 罗列竞品/方向，无三视角推导 | 商机是推导出来的；§3 逐一跑，跑不出飞轮就判「无」 |
| 报价格/竞品无来源 | §5 强制联网 + 分级标注，凭记忆报价 = 违规 |
| 两处数据矛盾却静默 | §5 显式裁决，取官方现价并说明另一处 |
| "能形成飞轮"含糊带过 | §3.2 写不出「资产 + 降低机制」就判「无飞轮」 |
| 建议隐含团队/融资 | §1 一人公司是硬约束，资本杠杆默认排除 |
| 分析未确认就写文件 | §2 第六部分只问一句，落库是 §6 的事 |
| 机会排序用叙事而非判据 | §4 六维打分，给「为什么一人能做」 |
| 全程只讲技术不讲钱 | §3.1 闭环要写出成本结构数字与验证门槛 |
| 获客写「内容营销/SEO」空泛带过 | §3.1 + §3.5：给具体渠道 + 第一个付费客户 |
| 不评估技术难度，默认「能做」 | §3.4：分级 + 里程碑，需自研底层判红灯 |
| 漏掉获客或原型维度 | 输出契约六部分缺一不可 |
