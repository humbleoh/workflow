# Concept-Toc — 教科书式目录生成

给定一个概念（任意宽度），以教科书作者视角生成**完整的树状目录**。核心原则：**目录即学习序列**——排序本身就是教学法；生成阶段独立于 vault，写入 vault 仅在用户确认后进行。

## 0. 与 concept-classify 的分工

| 用户要的 | 用哪个 |
| --- | --- |
| 为概念 X **生成**一份完整目录 / 大纲 / 知识树 | **本技能** |
| 把概念 X **归入** vault 已有结构（放哪个学科、哪个主题、哪一节） | concept-classify |

用户措辞同时含「分类」与「生成目录」时，以「是否要一份新目录」为准。

## 1. 输出合同（生成阶段，四部分按序，缺一不可）

1. **范围裁定**：概念的宽度分级（见 §2）+ 明确取舍（收录什么、不收什么、为什么）。**不盘问用户**——自行裁定并在此明说。
2. **目录树**：形态硬约束见 §3。渲染：四部分标题用 `##`；目录树整体降一级——部用 `###`、章用 `####`，节及更深层一律用嵌套列表项（节为一层缩进，目/条/款/项依深度继续缩进），无部时章用 `###`。
3. **编排逻辑**：一段话说明主线——先什么、后什么、为什么这个顺序可学。
4. **落地询问**：仅一句话——问用户「是否按 §4 写入 vault？」。位置提议与大纲转换内容属 §4 确认后的工作，**不得提前产出**（用户确认前可能还要改目录树，提前转换是白做）。

## 2. 宽度分级与规模参照

| 分级 | 例 | 规模 |
| --- | --- | --- |
| L1 领域级 | 线性代数、操作系统 | 3–7 部，共 10–16 章，每章 3–6 节 |
| L2 主题级 | 傅里叶变换、内存一致性模型 | 6–10 章，每章 3–6 节，不设部 |
| L3 机制级 | epoll、Rust 所有权 | 3–8 章，每章 2–5 节，含前置章与边界/比较章 |

超上限 = 过度展开，低于下限 = 覆盖不全；两处都回头修。规模落在两级之间的空档（如 7–9 章不设部）时，按较小分级的上限执行；确需更多则拆部升级。

## 3. 目录树硬约束

- **层级 ≤ 7**：默认 层级 ≤ 3（部 → 章 → 节；L2/L3 通常 章 → 节 两层）。确有需要（如 L1 领域级下某部内含需再分类的章群）可放宽至 7 层，第 4–7 层依次称「目」「条」「款」「项」，但**放宽须在范围裁定中说明理由**；能用两层表达的不用三层，依此类推——每多放宽一层都要有明确的组织收益，深度不是精细度的证明。落地为大纲时，第 3 层及以下均为嵌套列表项，第 4–7 层条目同样可落地为笔记。
- **禁止深度突变**：任一父节点下，子节点要么全是叶、要么全有子层。个别确需深挖的主题 → 拆成章或并列节，用括注收窄（如「收敛性：逐点、一致与均方」），不许孤零零多出一层。
- **每章 ≥ 2 节**；只有 1 节的章是假章，并入上级或拆成同级条目。
- **条目 = 主题名**：名词短语。**叶层条目必须中英并列**（如 `逆矩阵 Matrix Inverse`，将落地为笔记名）；部/章层不强制。**不写断言、结论、因果句、具体参数**。自检：叶层条目能否直接当一篇笔记的标题？章层能否当主题目录名？
  - ✅ `fork 与 epoll 的交互`
  - ❌ `fork 与 epoll：子进程不继承兴趣表`（断言可能错，目录不承担论断）
- **排序 = 学习顺序**：预备 → 原语/对象 → 机制/定理 → 方法/惯用法 → 应用 → 综述/边界/推广。与 vault 四层模型（原语 → 机制 → 惯用法 → 综述）同构。
  - **角色单调**：任一部/章内部，条目角色也应沿上列次序单调递进；出现「机制里夹原语」之类的回折，往往说明分组切错了——先重归部，再考虑改序。
  - **动手反馈前置（初学者大纲必守）**：面向初学者时，不允许全书过半才有第一个「能跑起来」的动手环节。应把最小可行实践（如最小命令行用法、hello-world）提前到原语章之后即出现，作为对心智模型的首次验证；完整工具链/深入用法仍留在惯用法层。
  - **抽象同层合并**：同一部内若多个条目实为同一机制的不同抽象层级（如 playbin ⊃ decodebin ⊃ autoplugger），合并为一个条目、按「从高层到低层」一层讲清，不为凑数拆成三条——初学者分不清未使用过的层次差异。
- **覆盖自检**：对照该领域经典教材 / 课程标准的章节共识，检查公认主干有无缺失；缺则补。不发明边缘分支凑数，不编造术语。
- **前置知识**：非本概念内部、但学习中必需的外部知识 → 开头集中为「预备知识」章/部（L3 常见），或在范围裁定中明确划出边界。**语言/运行时基础也算前置**：若后续有「用 X 语言编写」章，而该语言或其核心运行库（如 GLib 主循环）未在范围内，必须在预备知识中列出（可只给外部指引），不得作为隐藏门槛留给读者在应用章撞上。
- **附录可选**：只收速查表、符号表、延伸阅读，不承载正文主干；不编号。

## 4. 落地阶段（仅在用户确认后；确认前零写入）

1. **位置裁定**（向用户提议并获批；此时确认 `反刍/` vault 存在）：
   - 并入现有主题 → 合入该主题 `0. 大纲.md` 的序列，新条目按学习序插入其既有顺序中；
   - 新主题目录 → `<学科>/<主题> <英文>/0. 大纲.md`（新建目录属结构性变更，须用户点头）；
   - vault 无该学科 → 新建学科目录（中英并列命名），同样须获批。
2. **格式转换**（实证样本：`C++/并发编程/0. 大纲.md`、`Operating System 操作系统/实时调度 Real-Time Scheduling/0. 大纲.md`）：
   - `# <主题> 大纲` + 一段主题句（本目录回答什么问题）；
   - `## 序列`（或 `## 阅读序列`）：条目 = `[[笔记名|显示名]] —— **角色**：一句话说明`，角色取 前置/原语/机制/惯用法/应用/综述（封闭枚举，不自造角色词）；中文译名无社区共识时保留英文原词作显示名；
   - **TODO 与链接成对**：逐条判断该笔记是否已存在于 vault——已存在 → 直接 `[[笔记名|显示名]]`；不存在 → `*(TODO)* [[笔记名|显示名]]`。不得只留其一（只有链接无 TODO、或只有 TODO 无链接都算错）；转换前先探测既有笔记；
   - 模板固定含「范围边界」（2–4 条排除项）与「学习顺序」（一段话主线）两节，承接生成阶段的裁定结果；
   - 可选 `## 跨学科` 节：登记本主题依赖/被依赖的其他学科接口，指向对方大纲或待补笔记；其中悬空链接同样纳入校验；
   - 章分组用嵌套列表层级表达；
   - 文末 `>[!note]` 登记「本目录尚未覆盖」的边界项。
3. **接线**：在相关既有笔记或相邻主题大纲中补至少 1 条指向新大纲的链接，避免孤岛。
4. **校验后汇报**（落地前逐项过）：
   - 每个条目要么是真实存在的笔记链接，要么 `*(TODO)*` + 链接成对；
   - 文内所有 wiki-link 指向的路径真实存在，悬空者显式标 *待补*；
   - 与生成阶段目录树逐条 diff，无条目丢失/私增；
   - 反向接线 ≥ 1 条已落实。
   汇报：落地路径、结构变更点、未覆盖登记项。

## 5. 常见错误

| 错误                               | 纠正                      |
| -------------------------------- | ----------------------- |
| 同一棵树粒度混杂（个别条目下有 X.1–X.3，兄弟条目全扁平） | §3 禁止深度突变               |
| 条目写成断言 / 结论句                     | 条目只能当标题用                |
| 按字母序、重要性罗列，无学习序主线                | §3 排序原则 + 编排逻辑说明        |
| 未经确认就写文件                         | §4 第一句                  |
| 盘问用户要范围                          | 自行裁定，在范围裁定中明说           |
| 生成阶段就输出 wiki-link / 大纲格式         | 那是落地阶段的转换产物             |
| 规模失控（L3 概念写出十几章）                 | §2 规模参照，超限即压缩           |
| 确认前就产出位置提议或大纲转换内容                | §1 第 4 部分只问一句；那是 §4 的工作 |
| 全书过半才有第一个动手环节                     | §3 动手反馈前置：最小实践随原语章出现   |
| 章内角色回折（机制里夹原语）                   | §3 角色单调：先重归部再改序        |
| 同一机制的多个抽象层级拆成并列条目               | §3 抽象同层合并，从高层到低层一层讲清 |
| 隐藏语言/运行时前提（如 GLib、主循环）          | §3 前置知识：列入预备知识或范围边界    |
| TODO 标记与 wiki-link 只留其一          | §4 二者成对：不存在 = *(TODO)* + 链接 |
| 自造角色词（超出六角色枚举）                  | §4 角色为封闭枚举             |
