# Article-Critique — 初学者视角文档评审

评审的唯一产出是**问题清单**：找出「读者照着做会卡住」和「读完学不到东西」的地方。不是改写稿，不是最佳实践讲座，不是文字润色。

**收录判据**：这条问题不修，读者会**卡住**（无法继续）或**学错**（形成错误理解）吗？不会 → 不收录（至多并入琐碎合并条）。

## 读者画像

有一定基础的初学者：懂基础概念和语法，缺实践经验、体系理解、排错能力。

- 不需要解释「什么是变量」「什么是命令行」这类基础
- 需要：每条命令抄了能不能跑、每个新概念从哪来、每个阶段做完怎么确认对没错

## 评审方法：模拟执行（问题的唯一来源）

逐段通读，把自己当成这名读者，在脑中一步步照做，边做边记：

- **每个命令/代码块**：照抄能跑吗？依赖装了吗？版本对吗？**上一步的产物满足这一步的输入吗？**（前后步骤接得上吗）
- **每个新概念**：前文有铺垫吗？还是突然冒出？
- **每个阶段结束**：我怎么确认自己做对了？预期输出写的什么？

凡「这里我会犹豫/卡住/疑惑」的点全部记下——先记录，不评判，最后再按判据筛选。

无法实际运行时，至少完成**纸面推演**：逐条检查命令的前置依赖、参数含义、环境差异（OS、版本、端口占用）、步骤产物衔接。

## 检查清单

模拟执行完，用 6 类问题归档所有记录：

1. **路径完整性**（最重要）：魔法步骤（给了命令但没讲用途和关键参数）；依赖后文才讲、或根本没讲的知识；概念先解释再用，还是用到时才补；工具/格式/产物名首现零注解（gst-launch、Ogg 类名字裸奔，读者不知所云）；指称无先行词（「这带来 N 个问题」「两笔代价」「同一个问题」「两种答案」类概称未点名映射对象，读者得往前翻猜）；对应无映射（并列两组名物并称「对应」却不逐对点明——如类别一串、元素一串，读者只能猜谁对谁）
2. **可验证性**：每个阶段有无预期输出/验证方法；做错能否尽早发现，而不是最后才失败；实测断言环境不可判（只写「本机 / 本地」，不给版本与平台，读者无法核对自己环境能否复现）
3. **认知负荷**：单次引入的新概念/新工具是否超过 1–2 个；核心路径与可选内容混在一起；正文直接甩来源原句（英文引文无中文引入、先引后释），转述＋句尾缀链接更省读者
4. **错误路径**：常见报错、环境差异、版本问题是否覆盖；理想路径之外有无「失败了怎么办」
5. **解释深度**：基础「是什么」解释是否过多；是否缺「为何这样设计」「为何不那样做」「何时不该用」；循环解释（用被定义词自身定义术语，如拿「对象实例」解释「对象」）；归因断点（总起句「A 带来 N 个问题」与分论点前提不一致——前提不同源却归于一因）；机制关系方向不明（谁建立在谁上、交叉点往哪走）；答句腔段落（以回答姿态直入——「先明确 X」「所谓 Y 是指」，未先交代这段在回应什么，读者接不上上下文；关键概念只用括注带过、无成句定义同属此类）
6. **准确性**：命令、代码、版本号、路径能否照抄运行；术语前后是否一致；术语与本体错位（如把类型 ID 说成注册表——「X 是 Y」未核对 X 的本体归属）；图文不同步（图缺正文已讲的关键步骤，或正文修订后图未跟上）

## 严重度定义（排序依据）

| 级 | 定义 | 典型特征 |
| --- | --- | --- |
| 高 | 照做**必然失败**，或结果与文中所述矛盾 | 命令跑不通；步骤顺序自相矛盾；版本不存在 |
| 中 | **卡住需外部求助**，或会**形成错误理解** | 魔法参数后文依赖；概念突然出现且后文反复使用 |
| 低 | 能走完，但**绕路 / 无法验证 / 不知道对没对** | 缺验证步骤；可选项混进主线；术语不一致 |

## 输出契约

评审结果 = **最多 8 条**问题，按严重度高→中→低排序，输出前不加总体评价、不附全文改写稿。每条必须用以下结构：

```markdown
### N.〔高｜中｜低〕一句话问题标题

- **位置**：章节/段落，引用原文关键短语定位
- **类型**：检查清单编号（1–6）
- **读者状态**：他刚做了什么 → 卡在哪一步。必须写成具体动作序列
  （如「照抄了 `docker-compose up`，报 port already allocated」），
  禁止写成「读者可能感到困惑」式抽象形容
- **改法**：具体怎么改，可直接执行；只给最小修改片段，不重写全文
```

不足 8 条就少列；琐碎问题合并进相邻条目；全文确实没有问题就明说没有，不硬凑。

## 常见错误

| 错误 | 纠正 |
| --- | --- |
| 列 10+ 条流水账 | 契约上限 8 条：先按收录判据砍，再合并同类 |
| 「读者可能困惑/迷失」式抽象描述 | 读者状态必须是动作序列：做了什么 → 看到什么/卡在哪 |
| 以最佳实践讲座为主体（层缓存、安全加固、性能优化…） | 用收录判据过滤：读者不卡住、不学错 → 不收 |
| 先写总体好评再列问题 | 输出只有问题清单，无开场评语 |
| 按文章行文顺序罗列 | 按严重度高→中→低排序 |
| 附整篇改写稿/重写代码 | 只给最小修改片段 |
| 发现的问题全是「准确性」级小错，漏掉步骤衔接断点 | 模拟执行时重点检查上一步产物与下一步输入的衔接 |
| 把指称不明、对应无映射、答句腔、归因断点当「文风小毛病」不收录 | 按后果收录：读者要往前翻猜指代 / 建立错误映射 / 接不上上下文 = 卡住或学错，收录 |
