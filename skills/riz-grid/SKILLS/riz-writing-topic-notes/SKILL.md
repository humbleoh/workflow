# Writing-Topic-Notes — 大纲条目笔记撰写

给定主题大纲中的一个条目，写出一篇**初学者可读**、符合 vault 契约的笔记。核心原则：**笔记是其大纲条目的忠实展开**——角色定重心、技术断言逐一可溯源（依据内嵌正文）、例子先于机制、**因果与取舍讲透、干货落地**、**文风朴实、高信息密度**、形式从库惯例、与姊妹条目划清边界、**前置概念不卡读者**。流程四阶段：挖惯例 → 收依据 → 写正文 → 接线；交付前自检必须全过。

初学者要的不是结论清单，而是结论怎么来的；故「因果、设计取舍、历史成因讲透 + 干货落地」是本技能的硬要求（见阶段三「深度契约」）——这也是它与「手册拷贝」的分界。

## 1. 分工

| 用户要的             | 用                |
| ---------------- | ---------------- |
| 为大纲中某条目写一篇笔记     | **本技能**          |
| 为概念生成完整目录/大纲     | concept-toc      |
| 把既有概念归入 vault 结构 | concept-classify |

## 2. 阶段一：挖惯例（必做第一步）

按序读：
1. 主题的 `0. 大纲.md` 全文——目标条目名（中英）、**角色**（前置/原语/机制/惯用法/应用/综述）、一句话职责、所属章节；序列递进逻辑、范围边界声明与未覆盖登记。**据序列与边界声明定出本篇前置概念**：排在它之前的条目 + 边界点名的外部主题
2. ≥1 篇同主题已写笔记作结构模板，**优先同角色**（写惯用法就看已写的惯用法篇）；本主题尚无已写笔记时，取相邻主题一篇（如 `C++/并发编程/`、`Operating System 操作系统/实时调度 Real-Time Scheduling/`）
3. 条目的姊妹条目（同章相邻篇）——确认各自管辖面，避免重复

角色定重心：前置笔记回答「为什么需要它」并给对照基线；原语笔记给全控制面（身份、位置、设置/清除、效果清单）；机制笔记追问「怎么实现、边界在哪」（机制 + 边界 + 反例 + 证据）；惯用法笔记以「何时用、怎么写、怎么防误用」为中心，机制本体引回机制篇；应用笔记落一个完整方案，细节可转引；综述笔记给对照表与选型路径。**前置概念对所有角色成立**，不专属「前置」角色——读者是初学者，凡依赖未展开知识即须在开篇交代（见阶段三）。**深度契约（见阶段三）亦对所有角色成立**：机制/原语篇讲清「为何这样设计」，惯用法/应用篇讲清「为何这样选」，综述篇讲清「为何演化成这样」。

## 3. 阶段二：收依据（契约与预算）

权威分级（级别随链接文字或附录标注；正文引用以链接内嵌呈现）：

| 级   | 来源                                         | 用法                                                                                                        |
| --- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| 1   | 官方文档：语言标准、参考手册（RM）、应用笔记（AN）                | 定义与语义的首要依据；正文中文转述＋句尾缀链接，`§章节（±页码）`紧随其后；逐字引文不上正文，进 references 底账                                    |
| 1   | 本地实验（实际运行代码 / 上板实测）                        | 行为类断言的首要依据；正文标「实测」                                                                                        |
| 2   | 官方实现源码/头文件/例程、官方 KB、官方员工在官方论坛的答复、PEP、经典教材  | 设计动机、实现细节、官方对行为的定性；员工原话可 `> [!quote]`。**源码逐行实核**时对行为类断言是一手证据、强度等价 1 级——以链接内嵌到文件（含行号）呈现；仅给章节锚点未逐字核的，链接只到章节 |
| 2   | 社区实测线程（他人上板/运行的实录）                         | 无本地实验条件时的行为依据；标「实测」+ 链接                                                                                   |
| 3   | 权威二级来源（cppreference 类、Stack Overflow 高票实测） | 辅助，标注「编辑性概述」，引用附链接                                                                                        |
| 4   | 博客                                         | 仅取直觉与图解，不作断言依据                                                                                            |

规则：
- **依据强度体现在链接精确度**：**逐行实核** → 链接内嵌到文件（含行号）；**章节级锚点** → 链接只到章节、未逐字核；**未核** → 无链接、内联「待考」；**推断** → 内联「（推断）」并给理由。正文不用「实核 / 转引」这类孤立加粗标记——链接本身就是出处标注
- **必须实际查阅，禁止凭记忆落笔**：用 webfetch / context7 / librarian 查官方文档；「会怎样」类行为优先本地实验，无条件实验时引 2 级实测来源
- **依据内嵌正文，一步点达**：凡有据断言，先说人话（中文陈述），在线来源以空文本链接 `[](URL)` 直接缀在词后、不用圆括弧包裹（库内来源 `[[笔记]]` 同样缀尾），`§章节号（页码）`紧随其后（`[](URL) §64`）——断言是主角，出处是缀尾旁注；不写「（同上）」，同一来源的多处断言各自挂链接。**逐字引文原则上不上正文**（先甩原句后解释会打断初学者）：正文转述＋缀尾链接即可溯源，逐字原文留 references 底账；确需正文逐字时，先给一句中文引入再引，引入标记用「原文：」、不用「逐字：」。确无链接的来源（纸质书等离线资料）在附录注明获取方式
- **本地电子书可链接定位，不算「离线」**：vault 内已有电子书 PDF 的经典教材，先经 pdf 工具（检索/读页）定位并核对原文，再引 `[[books/书名.pdf#page=N|…]]`——页码进锚点，**不写进正文文字**；正文旁注出处用下标小图标 `<sub style="font-size:0.6em">[[books/…#page=N|↗]]</sub>`，不加圆括弧；表格依据格用 `[[…|⧉]]`（下标样式在表格内不用）；逐字引用处用 `> [!quote]` + 描述性别名作标题（如 `[[…|书名/§1.1]]`），callout 类型已表明逐字，标题不写「逐字引自」。书页码与 PDF 页码常相差前置页数，不一致时正文提书页码、锚点给 PDF 页码。**书中有对应原文的断言，不再引幻灯片/二手转述**；仅某版本独有的内容保留该版本出处并注明
- **转引复用**：库内既有笔记已核过的依据可经 `[[笔记]]` 内嵌转引（`[[X]]` 本身即链接、天然标注「经 X 转引」）——**不占查阅预算**；但转引不得超出原笔记核过的断言范围。前置/姊妹笔记已核的**反例**可转引为本篇动机段的因果起点（如「3.4 反例一」引出本篇盲区），不占预算
- **不可得诚实标记**：来源不可达（WAF 拦截等）时，用 `> [!info]` 说明获取状态，相关断言降级为内联「转引」/「待考」——诚实标记，不是省略
- **穷举断言须 grep 穷举**：「全库一致」「仅此 N 处」「仅此一条路径」类全称/存在性断言，必须 grep 全库检索并逐点列行号，不得凭印象写「应该就这几处」；行号内嵌进正文链接（`[sector_write.c L412](URL)`），注释逐字处用 `> [!quote]` 摘录
- **预算：新增依据收集至多 6 轮工具调用**（如 2 次查文档 + 2 次实验 + 2 次补缺；下载图片、看图核对也计入）。到额即开始写作——不够的信息标「待考」，不是延长研究的理由
- **预算内优先级**：先核高价值项——机制本体 / 判据常量 > 触发条件 / 边界 / 反例 > 设计动机 / 历史成因 / 定值理由（末类取证成功率最低，一轮查不到即标「待考」，预算让位给前两类）
- **「为何」类断言另立取证**：设计动机引官方设计理由（源码注释、应用笔记、官方 KB、官方员工答复），历史成因引旧版文档、标准修订史、勘误（errata）、迁移指南；与「是什么」类断言同等严格，**不得凭常识替设计师编动机**
- 版本/型号敏感的语法与行为，行内标注（如 (3.10+)、H753 vs H743）

## 4. 阶段三：写正文（结构契约）

笔记骨架，按序：

1. `# 中文名 English Name`——与大纲条目同名（文件名亦然）
2. 开篇段：`**术语**：一句话定义 + 一句话在本主题中的位置`。定义不可循环——不用被定义词或其同位语自证，从内存/机制层给非循环解释；「X 是 Y」先核 X 的本体归属（如 GType 是数值 ID，注册表属于类型系统）。**与姊妹条目有重叠面时，此处即给边界声明**——「X 的机制本体在 [[Y]]；本篇是第 N 章惯用法，回答 Z」；视角差异一句话点明（如「那是静态状态视角，本篇是动态转移视角」）。**主题问句前置**：开篇即点明本篇回答的核心问题（「本篇的主题是 X，回答一个问题：Y」）；「不展开、归姊妹篇」类路由压缩成短句缀尾，不挤占主题位置
3. `> [!info] 前置阅读`——有前置概念时写，紧随开篇段：已写笔记列 `[[链接]]`，未写的标 `名（TODO 待落地）`。未写前置在正文首现处给一句最小定义（够读懂本篇即可，不展开）
4. `## 动机 / 问题背景`——机制出现前的问题（**因果起点**）；有真实历史成因时在此交代「何时 / 为何引入、留下什么兼容包袱」；应用/惯用法篇先摆出两个世界（如开发 vs 生产）的矛盾要求；必要时用 `> [!info]` 说明笔记定位或依据获取状态
5. `## 定义与机制`——主体。认知顺序：最小例子 → 机制讲解（**因果链显式成链 + 设计取舍**）→ 边界与反例 → `### 速查`；母题对接例证（如「GStreamer 侧对接：」）放机制与边界之后殿后，不混进机制段打断叙述
   - **最小例子按域取形**：软件域给 ≤ 30 行可运行代码；嵌入式/硬件域给最小配置序列、官方源码片段（注明出处）、伪代码判定流程或分支树；例子引出后一句点明它正是开篇定义的最小兑现（定义里的术语各对应例中哪个物事），后文机制讲解优先回用例中的对象与代码行作锚，不让例子与主题脱钩
   - **源码删减摘录的忠实边界**：删减用 `...` 显式标注；**守卫条件、判据分支、状态位序列不得删**——删的是样板（如重复的分配调用）而非语义分支；关键逻辑被删处，用注释补足被删步骤的语义，不得让控制流读起来变味
   - **表格只在真需对照时用，因果叙事为主**：机制讲解以「因果链成段」为主体，不把每个断言拆成「断言 | 依据」格（那是碎片化清单，不是讲解）。确需对照表（分支树、两模式对照）时，依据格用**内嵌链接**（`[file.c L412](URL)`、`[[笔记]]`），禁止无链接的裸来源名
   - 误解、工程陷阱、归因陷阱（工具假象先归因再下结论）、待考边界清单，用 `> [!warning]`
   - 末尾 `### 速查` 表收束：「维度 → 值」或「问题 → 答案」
6. `## 与相关概念的关系`——关系类型：**上位 / 上游 / 同层 / 对照 / 下游 / 跨学科**；已写笔记用 `[[链接]]`，未写的标 TODO（带章节号）
7. `## 相关笔记`（可选，随库惯例）——纯 `[[链接]]` 跳转列表，不写关系注解；与上节分工：上节答「它和谁是什么关系」，本节只答「还有谁值得点过去看」；两者并存时，本节不含已在上节出现的链接
8. `>[!references]`（附录，只放正文放不下的）——**本地实验底账**（完整命令、参数、环境版本；正文只留场景与数字）、**逐字引文底账**（正文转述处的原文摘录）、**离线无链接来源**（纸质书等，注明获取方式）、**待考项清单**（正文内联「待考」的汇总与原因）、**图片来源**（来源图出处 / 自绘图依据）。正文已内嵌链接的来源**不重复罗列**，否则又是双份

### 深度契约（所有角色都成立）

初学者的困难不在「记不住结论」，而在「不知结论从何而来、为何长成这样」。凡有据可查处，正文必须回答三问；无据不写、不编：

| 问 | 要讲什么 | 未讲透的判据 |
| --- | --- | --- |
| **因果** | 机制 / 参数 → 后果 → 后果的后果，显式成链（如「03h 零空周期 → 器件无准备时间 → 被单独降档至 50 MHz」） | 删掉中间环节，读者能否自行补上？不能即未讲透 |
| **设计取舍** | 有别的做法吗？为何选它？代价是什么？代价由哪个具体设计决定造成、谁买单？ | 只说了「它是这样」，没说「为何不是那样」；代价未落到具体设计决定 + 结构级证据（字段表/签名）+ 买单方 |
| **历史成因** | 何时 / 为何引入？留下什么兼容包袱？ | 怪设计被当成「本来就该这样」 |

- **取证**：三问同受阶段二约束——设计动机引官方理由（源码注释、应用笔记、官方 KB、官方员工答复），历史引旧版文档 / 标准修订史 / 勘误（errata）/ 迁移指南；查不到内联「待考」，**不得凭常识替设计师编动机**（推断内联「（推断）」并给理由）
- **落点**：篇幅小则融入相关段（因果链融进机制讲解，历史成因放动机段），成体系则单开一小节；不强制独立标题，禁止为凑结构造空节
- **边界**：只讲与本篇角色相关的「为何」；无关的动机 / 历史 `[[引走]]` 给兄弟条目

**干货**：可直接影响判断或决策、且读者自己想不到 / 查不到的具体信息。四种形态——**数字**（阈值、上限、量级、比例）、**公式**（把关系写成式子）、**判定规则**（何时选哪个：决策表 / 分支树）、**反直觉结论与生产坑**。

> [!warning] 反判据：堆参数不是干货
> 参数罗列、面面俱到的选项清单、复述手册目录、无决策含义的「完整性」都不是干货。判据：**删掉它，读者做决策会不会错？** 会 → 干货；只是「更完整」→ 手册拷贝，删。

库内达标样本（照此手感写）：
- 因果链 + 设计取舍 + 反直觉结论：[[标准 SPI 的带宽瓶颈 Standard SPI Bandwidth Bottleneck]]（「空周期不是浪费，是买频率的门票」；「133 MHz 是除 03h 外所有命令的上限」）
- 历史成因 + 兼容包袱：[[长文件名与 Unicode Long File Names and Unicode]]（「FAT 诞生时……又不能破坏老系统——于是……」）
- 官方设计取舍逐字：[[SFDP 参数表 SFDP Parameter Table]]（引 `sfdp.c` 注释说明「一次读全部参数头」的取舍）

行文规则（操作化定义）：
- **深入浅出** = 例子先于机制先于边界
- **不啰嗦** = 无开篇俗话、无复述正文的总结段、每段都载信息；
- **朴实** = 平实直陈，修饰最小化：无感叹号、无排比与抒情修辞、无「值得一提 / 众所周知 / 毋庸置疑」类填充语；无「钉死 / 摆齐 / 划清界限 / 自证」类修辞化动词（改直陈：定义 / 并列 / 区分 / 体现）；形容词副词能删则删，让断言与证据自己说话
- **高密度** = 每句必载新信息：无空洞过渡句、无同义反复；短句直给，一句一个断言或一个因果步
- **流畅** = 段间衔接自然、无逻辑跳步，读者无需回看补上下文
- **因果显式** = 把「因为 → 所以 → 导致」写出来，不把推导留给读者；面向初学者，越是自己觉得「显然」处越要展开
- **实测叙述平实成场景** = 实测断言写成「做了什么 → 看到什么 → 数字说明什么」的平实场景，并点明实测对象与目的（验证哪条行为断言、给正文哪处论证供证），不写「（实测：数字）」式括弧快照旁注；完整命令、参数、文件名不进正文（references 本地实验条目记录），不添「亲手」「称一帧的重量」类表演性动词与比喻——数字与算式自己说话
- **实测表述环境中性** = 正文不写「本机 / 本地」类个人视角词，环境用版本表述（「GStreamer 1.28.2 实测」）；环境与完整命令底账在 references
- **动用的名字首现即注** = 正文使用的工具、格式、产物名（如 gst-launch-1.0、Ogg、WAV）首现处给一句白话：谁制定、是什么、通常干什么——「可独立阅读」的承诺覆盖它们，不只是前置笔记
- **总起对账** = 总起句声称「A 带来 N 个问题/代价」时，逐个核对分论点前提确能从 A 推出；前提不同源就并列、各表前提，不强行归于一因（虚假归因比无总起更误导）
- **概称词点名** = 「这 N 个问题」「两笔代价」「一件东西」类概称与代词，首现处点名映射对象，后文方可复用
- **叙述体成文，不用答句腔** = 段落按文章自身叙事展开：从上文自然引出对象再下定义，关键新概念给成句定义而非括注带过（如「元素类别——每个元素注册时附带的层级分类字符串」）；禁止「先明确 X」「所谓 Y 是指」类回答姿态开段——正文是文章不是答问，所谈问题的上下文由正文自己给出
- **关系写方向** = 讲两个机制的关系显式写谁建立在谁上、交叉点往哪走（如「属性变化的通知借信号发出」），不用「相关/配合」含糊带过
- **对应断言逐对点明** = 称「A 与 B 对应」时逐对给出映射——对照表逐行「A｜B｜各自角色」，或句中成对点名；两串各自裸列（如类别一串、元素一串）不算讲了对应
- **成段展开** = 初学者读的是讲解不是私人速记：每个要点写成完整句段（主张 → 现实/机制 → 由此产生的后果与应对），条目清单只作骨架不作最终形态
- **歧义词先拆维度** = 术语混含多个独立概念时（如「集中」＝逻辑/物理/管理三件事），先显式列出各维度，再让例子逐维度对号入座；不指望读者从「集中式」自行联想到「逻辑上集中」
- **中文术语准确** = 取该领域标准译名；无标准译名用通行译名并保留英文；不直译、不造词
- 中文正文；术语首现中英并列；缩写首现旁标全称（`速率单调调度（Rate-Monotonic Scheduling, RM）`），后文方可只用缩写；标识符用行内代码；数学用 $…$
- **待考/推断内联轻量**：「待考」「（推断）」内联在句子流中、不加粗、不打断阅读；推断给理由（如「推断自执行位置模型」）。取证状态不是正文主角，链接与断言才是

图片规则（需要才用，宁缺毋滥）：
- **何时用**：结构关系、分类树、流程/状态机、时序等纯文字表述吃力处；一篇 0–5 张，不为配图而配图。图是表达工具，不是断言依据（官方文档原图除外）
- **来源优先级**：官方文档/数据手册原图 > 经典教材插图 > 社区图解；不用营销图、水印图、与正文所述版本不符的旧版图；无合格现成图、或现成图与正文角度/版本不符时，**自绘**（见下条）
- **两条获取途径**：
  - **下载**：现成图经 webfetch / `curl -L` 下载
  - **自绘**：手段按图选形——结构图、分类树、分支树手写 SVG；流程、状态机、时序用 PlantUML 代码块（vault 惯例；首行 `skinparam defaultFontName "Noto Sans Mono CJK SC"` 定中文字体，PlantUML 插件输出 SVG 天然清晰，不用 dpi/zoom 调尺寸），Mermaid 备选；直接写在正文，不产生图片文件；数据图、函数图用脚本生成（graphviz、matplotlib 等）；布局复杂或拿不准的图可丢给多模态模型（经 task 委派视觉向子代理，如 visual-engineering），只交代内容要点、格式与术语要求。无论亲自写还是委派，图中内容只能图解正文**已核实**的断言，不得借图引入新断言
- **存放**（文件类图统一）：vault 根目录 `pictures/`；文件名用描述性中文（如 `函数调用形式.png`），不用 `Pasted image …` 时间戳名；保留原格式（png/jpg/svg/webp 均可）
- **必须实际渲染核对（下载图与自绘图一律，委派产物同）**：下载图下载后打开、自绘图定稿后渲染打开、Mermaid 预览渲染——确认内容支撑正文断言、图中标注与正文术语一致、无文字重叠或截断；图文不符宁可不用
- **图文断言对照，修订后回查**：图的每条边、每个标注能指认对应正文哪条断言；正文修订后回查图并同步（正文把直连改出两跳寻址，图的压缩边要跟着拆）——初学者应能仅凭图重建正文机制路径，缺步即改图
- **引用**：文件图用 `![[文件名.png]]`，需要控宽时 `![[文件名.png|400]]`；Mermaid 直接是正文代码块。来源图在 references 按级列出（链接 + 出处章节，注明「图解了哪条断言」）；自绘图在 references 注明「自绘（依据正文哪条断言）」，不占来源分级

## 常见错误

| 错误                | 纠正                                                   |
| ----------------- | ---------------------------------------------------- |
| 「这我知道」，凭记忆直接写     | 记忆不是依据；查文档/跑实验/找实录，自检第 1 条会拦截                        |
| 论坛见过的结论，凭印象复述     | 社区实测可作 2 级依据，但必须给链接；找不到就标「待考」                        |
| 无限追查来源，迟迟不动笔      | 6 轮预算（转引不占）；到额用现有材料写，缺口标「待考」                         |
| 来源打不开就绕开不写        | 标「转引/待考」+ `> [!info]` 说明获取状态——诚实降级，不是省略              |
| 参数选项面面俱到、堆成手册     | 角色定重心：机制笔记追机制与边界，不做手册拷贝                              |
| 笔记之间内容重叠、各说一遍     | 开篇边界声明：本体归机制/原语篇，本篇只答自己角色的那个问题，其余 `[[引走]]`           |
| 前置概念没交代，读者卡在半路    | 开篇 `> [!info] 前置阅读` 列已写前置；未写的正文首现给最小定义               |
| 表格只给结论            | 关键断言表加「依据」列——结论与证据同格                                 |
| 网上抓图不打开就用         | 必须看图核对——图文不符比没图更误导                                   |
| 图随手存、用默认时间戳名      | 统一存 vault 根 `pictures/`，描述性中文命名，正文 `![[文件名.png]]` 引用 |
| 为配图而配图            | 图是表达工具：文字说不清时才用；一篇 0–5 张                             |
| 官方无现成图就硬凑旧图或弃图    | 可自绘或委派多模态模型：SVG / Mermaid / 脚本生成；图中只放正文已核实的断言                |
| references 罗列正文已内嵌的来源 | references 只留附录：本地实验底账 + 逐字引文底账 + 离线来源 + 待考清单 + 图片出处，已内嵌来源不重复                            |
| 用「(4.3 实核)」这类标记代替链接 | 依据内嵌正文：断言＋句尾 `[](URL)` / `[[笔记]]`，`§章节` 紧随其后，不留孤立标记 |
| 正文甩英文原句当论据 | 先说人话＋句尾缀链接；逐字底账进 references，确需逐字先给中文引入 |
| 实测把完整命令连参数抄进正文场景 | 正文留「动作 → 所见 → 数字」；完整命令入 references 本地实验条目 |
| gst-launch、Ogg 类名字裸奔出现 | 首现处一句白话：谁制定、是什么、干什么用 |
| 待考/推断在正文加粗打断 | 取证状态内联不加粗；链接与断言是正文主角，取证是旁注      |
| 笔记写完，大纲条目还是 TODO  | 接线是「写完」的一部分，不是可选项                                    |
| 例子跑不通 / 注释与实际输出不符 | 自检第 3 条；未验证的例子宁可删                                    |
| 只给结论，不给因果         | 因果链显式成链（深度契约）；删掉中间环节读者能否补上？不能即未讲透                     |
| 总起句「A 带来 N 个问题」，分论点前提各不相同 | 总起对账：前提不同源就并列各表前提；虚假归因比无总起更误导 |
| 用被定义词定义术语（拿「对象实例」解释「对象」） | 从内存/机制层给非循环定义 |
| 「一件东西」「两笔代价」类概称无先行词 | 首现处点名映射对象，后文方可复用 |
| 只讲「它是这样」，不讲「为何不是那样」 | 给备选做法与代价（设计取舍）；不做对比不算讲透                               |
| 把怪设计当成理所当然        | 查历史成因与兼容包袱；查不到标「待考」，不编                                |
| 凭常识替设计师编动机        | 动机须引官方理由；推断注明「（推断）」并给理由                               |
| 辞藻修辞、抒情过渡、「钉死 / 摆齐」类修辞化动词凑篇幅 | 朴实高密度：直陈事实，改用「定义 / 并列 / 体现 / 区分」等直陈动词 |
| 干货 = 参数罗列          | 反判据：删掉它读者做决策会不会错？不会 → 删                |
| 手头有书仍引幻灯片/转述外链     | 经 pdf 工具定位核对后引 `[[books/x.pdf#page=N\|⧉]]`；书里没有的内容保留原出处     |
| 要点是速记片段，初学者跟不上    | 成段展开：主张 → 现实/机制 → 后果与应对；条目清单只是草稿骨架      |
| 一词多义不拆维度直接举例      | 先显式列出术语混含的几件事（维度），再让例子逐维度对号入座         |
| 段落以「先明确两个指称」类答句腔开写 | 叙述体成文：从上文自然引出对象再下定义，上下文由正文自己给 |
| 「类别一串、元素一串」两串裸列称「对应」 | 对照表逐行或句中成对点名「谁对谁、各自行使什么」 |
| 正文写「本机 / 本地」类个人视角词 | 环境中性表述（「GStreamer 1.28.2 实测」），环境与命令底账在 references |
| 「这个闭环」类牵强概称词 | 直呼其物（「这个最小例子」）；修辞化名词与「钉死/摆齐」同罪 |
| 出处写成「（[send(2)](URL)）」带名括弧式 | 空文本链接 ` [](URL)` 直接缀词后，无括弧无名字；PDF 旁注用 `<sub>…↗…</sub>` |
| 「逐字引自」入 quote 标题、「逐字：」入正文 | callout 类型已表明逐字，标题只给出处；行内原文用「原文：」 |
