# Riz-Niche-Scout — 商机探索（机会优先，未给定技术）

给定的是硬约束而非技术：可软件化、可自动化、利基、一人公司、短期可实现。核心原则：**方向是筛出来的，不是罗列出来的**——先起点裁定、候选生成、逐候选过硬约束门，再取证与排序；问题存在 ≠ 付费意愿，两级分开判；每条断言带证据分级；先对话输出，用户确认后才写 vault。

## 1. 分工

| 用户要的 | 用 |
| --- | --- |
| 未给定技术，按约束找方向 / 筛机会 | **本技能** |
| 给定一个技术，探索它的商机与前景 | riz-biz-explore |
| 为概念生成目录 / 大纲 | concept-toc |
| 纯开发任务（实现 / 重构 / 评估代码难度） | 不用本技能 |

## 2. 输出契约（分析阶段，七部分按序，缺一不可）

1. **起点裁定**：从用户消息与上下文（职业 / 领域 / 既有技能 / 人群触点 / 痛点观察）提取**起点**。有起点 → 开头一句话声明用哪个、为什么；无起点 → **明说「用户未给起点」**，自行裁定扫描锚点（市场 / 语言 / 社区范围）并给理由。不盘问用户，自行裁定并明说。
2. **候选生成**：4–8 个候选，一行一个（人群 / 痛点 / 一句方案）。有起点 → 用人群 × 痛点矩阵扩展起点；无起点 → 按锚点扫描社区痛点帖、付费工具差评、新法规 / 平台变化。
3. **硬约束门**：**逐候选**判五门（不许对候选池整体只判一次）；门只有 pass / fail 两值，拿不准按 fail（保守出局）；**任一 fail 当场出局，不进深析**，后续取证、排序、获客只为过门候选花——
   可软件化；可自动化（交付后单客边际人力趋零）；利基（人群窄到点得名为社区，大厂看不上）；一人可交付（开发 + 维护 + 客服一人扛得住，含法规 / 平台变动的后续维护）；短期（1–3 月出可 demo 原型，无自研底层、无未稳定依赖）。
4. **需求侧取证**：每候选 ≥2 条带链接的用户原话（求助帖 / 付费差评 / 招聘 / 外包单）。**两级判定，不得合并**：
   - 问题存在（手搓 / 抱怨 / 绕行）=「问题有据」；
   - 付费意愿（已在为替代方案花钱：现付费工具 / 外包预算 / 专人岗位）=「付费意愿有据」。
   - 只有前者 → 付费意愿**待验**，报告中明写，且该方向在 §2.6 优先安排验证。
5. **快筛排序**：八维判据表（§4）。需求真实性与获客可及性是一票否决门（0 分即出局，不参与加总）；每维给一句依据，不许裸数字；每方向一句「为什么一人能做」。
6. **验证交接**：头部 1–2 方向各给一条**最廉证伪实验**（≤2 周、成本有上限：假门落地页收 waitlist / 社区预售收订金 / N 个目标客户访谈），并写明「不达标 → 转向哪条」。
7. **落地询问**：仅一句——「是否按 §7 写入 vault？」，且是全文最后一行；七部分之外不增设编号章节（TL;DR 一句话可置于开头）。

## 3. 研究预算（防无界扫描）

- 联网调研至多 **7 轮工具调用**，到额即开始写；取不到的缺口标**待考**并说明卡在哪。
- 按候选分批检索，一轮尽量覆盖同一锚点下的多个候选；不为单一方向无限下钻。
- 来源不可达 → 该断言降级为**待考**（加粗），禁止用记忆值顶替。

## 4. 快筛排序判据（八维，0 / 1 / 2 三级）

| 维度 | 问 |
| --- | --- |
| 需求真实性（否决门） | 问题有据？付费意愿有据？（问题都无据 = 0，出局） |
| 一人可交付 | 一人做得出来、维护得动？ |
| 成本结构 | 交付后可变成本趋零？ |
| 自动化度 | 交付 / 客服环节能自动化掉多少？ |
| 利基纯度 | 人群窄到点得名为社区？大厂看不上？ |
| 竞争格局 | 竞品存在 = 需求佐证 + 须答「大厂 / 另一个 indie 为何 3 月内吃不掉你」；零竞品 = 警惕无市场 |
| 短期原型 | 1–3 月可出可 demo 原型？ |
| 获客可及性（否决门） | 第一个付费客户的渠道点得出名？（点不出 = 0，出局） |

付费意愿计分：有据 = 2；待验 = 1（排序可靠前，但必须显式标注待验）；两者皆无 = 0。

## 5. 获客与杠杆（仅写通过快筛的方向）

- 获客：具体社区 / 渠道名 + 一句可执行动作（如「在 X 社区搜痛点原话 → 回复方案 → DM 免费帮搭」）。内容 / SEO 类渠道不作整体排除，但必须给具体动作与量化依据（首发地、频率、首个读者从哪来），空泛带过按违规计。
- 杠杆：技术 / 平台 / 网络 / 时间 / 媒体-受众，逐条判，命中才写；每条写「支点（特性）+ 动力（外部资源）」，缺一不可。资本杠杆默认排除。

## 6. 证据分级（所有断言带级）

同 riz-biz-explore §5：四级来源表（1 官方定价页 / 文档 / 一手实测；2 竞品官网 / 官方公告；3 权威二手，标「编辑性概述」；4 论坛 / 推测，仅取需求信号）。每条断言标 出处（链接）/ 推断（给理由）/ **待考**（加粗）；矛盾数据显式裁决；禁止凭记忆报价格、报市场规模。

## 7. 落地阶段（仅在用户确认后；确认前零写入）

1. **位置裁定**（提议并获批）：`反刍/` vault 下合适目录，遵循中英并列命名惯例。
2. **落库格式**：`# 标题` + 一句话结论 + `## 起点与锚点` + `## 候选与硬约束门` + `## 需求侧取证` + `## 快筛排序` + `## 最廉证伪实验` + `>[!references]`（按级列出，注明支撑了哪条断言）。
3. **接线**：相关既有笔记补 ≥1 条指向新笔记的链接。
4. **校验后汇报**：落库路径、结构变更点。

## 8. 常见错误

| 错误 | 纠正 |
| --- | --- |
| 无起点却不开口声明，凭空锚定市场 / 人群 | §2.1：明说「未给起点」+ 声明锚点与理由 |
| 门判成「△ / 保留观察」等第三态 | §2.3：门只有 pass / fail 两值，拿不准 = fail |
| 手搓 / 抱怨直接判「付费意愿已验证」 | §2.4 两级判定：只有手搓 → 付费意愿**待验** |
| 深析完才发现方向违反硬约束 | §2.3：门逐候选判，fail 即弃，取证不为出局者花 |
| 对候选池整体判一次门，逐候选门被跳过 | §2.3：五个门每个候选各判一遍，先于取证 |
| 凭记忆报价格 / 市场规模 | §3 + §6：联网取证，取不到标**待考** |
| 获客写「内容营销 / SEO」空泛带过 | §5：具体渠道 + 可执行动作 + 量化依据 |
| 排序给裸分数无依据 | §4：每维一句依据；否决门优先于总分 |
| 只给方向清单，无验证动作 | §2.6：头部方向各带最廉证伪实验与转向 |
| 未确认就写文件 | §2.7 + §7：确认前零写入 |
| 用户明明给了技术还用本技能 | §1：转 riz-biz-explore |
| 契约外增设「## 7. 结论」等编号章节 | §2.7：落地询问是第七部分，也是最后一行 |
